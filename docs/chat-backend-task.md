# Чат: задача бэкенду

**Всё выкачено, фронтенд переведён.** Файл оставлен как история решений и справка
по расхождениям с первоначальным черновиком.

После изменений обновить `nexus_project/documents/api/social.json` — фронтенд
перегенерирует типы (`pnpm api:types`).

## Что уже работает

- системные комнаты `general`, `movies`, `series`, `books`, `games` с полем `system`,
  участие у всех автоматически, в `GET /chats` первыми;
- `POST /api/v1/social/chat/rooms` — свою комнату заводит любой вошедший; два разных 409
  (`slug_taken`, `room_limit`), 429 с `retry_after` на суточном лимите;
- `owner: UserRef | null` в `CustomRoom`; `PATCH` и `DELETE /chat/rooms/{slug}` для владельца
  и админа; у системной — 403 `room_is_system`;
- жалобы: `POST /chat/rooms/{slug}/report`, админский листинг
  `GET /admin/chat/rooms/reports`;
- десять основных комнат заведены (слаги `what-to-watch` и `detectives` — не как в черновике
  ниже, остальные совпадают).

- активность комнат (`messages_24h`, `last_message_at`) и `sort` в каталоге;
- поиск: `?q=` по комнатам и `GET /chat/search` по сообщениям (в каждом элементе — `room`);
- `GET /social/users?q=` — автодополнение «@» по всем пользователям;
- канал `rooms` — новая комната появляется в списке без перезагрузки;
- `chat.mention` в личный канал;
- `PUT|DELETE /chat/rooms/{slug}/hidden` и поле `CustomRoom.hidden` — убрать общий чат
  из «Моих чатов» и вернуть обратно; только для системных комнат, на остальных 400;
- личные сообщения: `PUT /users/{username}/dm` → `ChatRoomInfo` (комната `dm:<id>`),
  `DELETE /chat/dm/{id}`, поле `dm: DmRef` и `kind: "dm"` в `ChatSummary`,
  событие `dm.created` в личный канал получателя (только при создании);
- блокировки: `PUT|DELETE /users/{username}/block`, `GET /users/blocked`,
  поля `blocked` и `blocked_by` в профиле. Поиск людей сам отфильтровывает обе стороны;
- `GET|PATCH /users/me/chat-settings` — `dm_policy: all | following | none`.

## Открытые задачи

### Вложения в сообщениях

Сейчас в чат можно «прикрепить» только карточку каталога, и то обходным путём: фронтенд
кладёт в текст ссылку вида `/films/dune-2021`, а под сообщением рисует превью, подтянув
карточку по слагу. Картинку, скриншот или файл отправить нельзя — в `ChatMessage` нет
поля под вложение.

Нужно:

- загрузка файла: `POST /api/v1/social/chat/attachments` (multipart) →
  `{ id, url, kind, width?, height?, size, name }`, где `kind` — `image | file`;
- в `ChatMessage` — поле `attachment: Attachment | null`; в `chat.send` по WebSocket —
  `attachment_id`;
- сообщение может быть только с вложением, без текста (сейчас тело обязательно);
- удаление сообщения снимает вложение.

Если это дорого — достаточно одних картинок: они закрывают почти все случаи.

## Расхождения с черновиком ниже (намеренные)

- лимит «5 живых комнат» отдаёт **409 `room_limit`**, а не 429: ждать нечего, надо удалить
  комнату. 429 с `retry_after` остался только на суточном лимите;
- `chat.mention` несёт `{kind, target_id, message}`, а не `{room, message}`: имени комнаты
  в личном канале взяться неоткуда, фронтенд сопоставляет по `kind` + `target_id`;
- слаги основных комнат — `what-to-watch` и `detectives` (в таблице ниже были `recommend`
  и `detective`).

## 1. Системные чаты (вкладки панели)

В панели чата вкладка — это сам чат, а не список. Нужны пять комнат, в которых состоят все.

| slug      | title     |
| --------- | --------- |
| `general` | Общий чат |
| `movies`  | Кино      |
| `series`  | Сериалы   |
| `books`   | Книги     |
| `games`   | Игры      |

Требования:

- добавить в `CustomRoom` поле `system: boolean` (по умолчанию `false`);
- системную комнату нельзя удалить, нельзя покинуть, нельзя создать через обычный эндпоинт;
- участником системной комнаты считается каждый зарегистрированный пользователь —
  и существующие, и все новые. Поэтому она всегда приходит в `GET /chats`, а её канал
  подписан на `user:`-соединении без явного `subscribe`;
- в `GET /chats` системные комнаты отдавать первыми;
- флаг выставляется миграцией, не через API.

Гость должен иметь возможность читать системные комнаты без входа (как сейчас читается
чат карточки).

## 2. Свои комнаты: создаёт любой пользователь

Сейчас комнаты заводит только админ (`POST /admin/chat/rooms`). Нужен публичный эндпоинт.

### `POST /api/v1/social/chat/rooms`

- требует вход и подтверждённый email;
- тело: `{ title: string (1–100), slug: string (1–80, `^[a-z0-9]+(?:-[a-z0-9]+)*$`), description?: string | null (≤500) }`;
- автор автоматически становится участником;
- ответ `201 CustomRoom`;
- ошибки: `409 conflict` — slug занят, `403 forbidden` — пользователь заблокирован,
  `429` с `retry_after` — лимит.

Ограничения (предложение, поправьте под свои правила):

- не больше **5 своих живых комнат** на пользователя;
- не больше **3 комнат в сутки**;
- зарезервированные слаги занять нельзя: `general`, `movies`, `series`, `books`, `games`,
  а также `admin`, `api`, `new`, `search`, `chat`.

### Владение и правка

- в `CustomRoom` добавить `owner: UserRef | null` (`null` — системная или заведённая админом);
- `PATCH /api/v1/social/chat/rooms/{slug}` — владелец меняет `title` и `description`;
  `slug` неизменен;
- `DELETE /api/v1/social/chat/rooms/{slug}` — владелец удаляет свою комнату вместе
  с сообщениями и участниками;
- админ может то же самое через существующие `/admin/chat/rooms/{slug}`;
- системную комнату не трогает никто.

### Модерация

- `POST /api/v1/social/chat/rooms/{slug}/report` с телом `{ reason: string (≤500) }` —
  жалоба на комнату; повторная жалоба того же пользователя не создаёт дубль;
- админу — список комнат с жалобами (можно отдельным полем `reports_count`
  в админском листинге, можно отдельным эндпоинтом; на ваше усмотрение).

### Реалтайм

- событие `chat.room.created` в общий канал каталога (или в `user:` всем) — чтобы каталог
  обновлялся без перезагрузки. Событие `chat.room.updated` и `chat.room.deleted` уже есть.

## 4. Активность комнат

- в `CustomRoom` добавить `last_message_at: string | null` (ISO) и `messages_24h: number` —
  сообщений за последние сутки;
- в `GET /api/v1/social/chat/rooms` добавить `sort: 'active' | 'members' | 'new'`
  (по умолчанию `active`):
  - `active` — по `messages_24h` убыв., при равенстве по `last_message_at` убыв.;
  - `members` — текущее поведение (`members_count` убыв.);
  - `new` — по `created_at` убыв.;
- счётчик должен быть дешёвым: материализованный счётчик, обновляемый при записи сообщения,
  или кэш с TTL в минуту — точность до минуты достаточна.

## 5. Поиск (Meilisearch)

По правилу проекта любой поиск и сортировка — только через Meilisearch.

- **по комнатам**: `GET /api/v1/social/chat/rooms?q=...` — по `title` и `description`,
  ответ тот же `Page_CustomRoom`, с опечатками и префиксным совпадением;
- **по сообщениям**: `GET /api/v1/social/chat/search?q=...&room=<kind:slug>&limit&before`
  — по телу сообщений в доступных пользователю комнатах; `room` необязателен (без него —
  по всем моим чатам). Ответ как `ChatHistory`, плюс в каждом элементе комната, чтобы
  фронтенд мог её открыть. Удалённые сообщения не индексируются; правка и удаление
  обновляют индекс.

---

## 6. Упоминания

- при сохранении сообщения разбирать `@username` (`[a-zA-Z0-9_]{1,32}`);
- для каждого существующего пользователя слать в его `user:`-канал событие `chat.mention`
  с `{ room, message }` — фронтенд покажет уведомление и подсветит;
- упоминание самого себя и упоминания в собственном сообщении пропускать;
- непрочитанное считается как сейчас.

## 7. Поиск пользователей (автодополнение «@»)

`GET /api/v1/social/users?q=...&limit=8` → список `UserRef`, поиск по `username`
и `display_name` через Meilisearch. Сейчас фронтенд подсказывает только тех, кто уже писал
в открытой комнате.
