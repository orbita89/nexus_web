## Правила

- Приняли решение, которое не видно из кода, — допишите его сюда с объяснением «почему».
- Нашли, чего не хватает в API, — в [backend-questions.md](backend-questions.md), код бэкенда
  отсюда не меняем.
- **Любая сортировка, фильтрация и поиск — только через поисковый индекс (Tantivy)** (`GET /search`,
  `GET /search/people`), не через PostgreSQL (`GET /entities` со списками, `?q=` по БД): из БД
  список каталога на dev шёл 6–8 с, из индекса — десятки миллисекунд. Чего нет в индексе —
  не обходим через БД, а ставим задачу бэкенду добавить это в индекс
  ([backend-prompt-meilisearch.md](backend-prompt-meilisearch.md)). Из БД — только одна запись по
  slug (карточка, тег, студия) и служебный обход каталога при сборке и в ISR.
- **Весь поиск — Tantivy** (книги с 2026-11-17, остальное с 2026-11-24; Meilisearch удалён).
  Без `SEARCH_INDEX_DIR` поиск отвечает 503. Пока индекс строится, выдача пустая — собранные в
  этот момент ISR-страницы пересобрать (`POST /admin/search/reindex/stream`). Запрос только про книги (`kind=book`) —
  отвечает книжный индекс: поиск по названию, автору и серии, автодополнение недописанного слова
  («прест» → «Преступление и наказание»), `ё` = `е`, исправление одной опечатки. В выдаче по
  всем разделам книги чередуются с остальными работами. Отличия книжной выдачи: в
  `EntitySummary` есть `authors` (карточка и подсказки показывают автора), работает фильтр
  `has_cover` (в адресе — `cover=1`, переключатель «С обложкой» в разделе «Книги»), сортировок
  меньше (`BOOK_SORTS` в `filters.ts`), жанров в панели — до 300. Страницы книг при сборке не
  пререндерятся (их сотни тысяч): страница собирается при первом заходе и дальше раздаётся
  как готовый HTML (`server/isr.js`); аннотация приходит один раз вместе с карточкой.
