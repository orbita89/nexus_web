# «Нравится» у произведения

На карточке фильма не хватает простого «мне понравилось». Сейчас у произведения есть:

- **оценка 1–10** (`PUT /social/entities/{slug}/review`) — это рецензия, её надо обдумать;
- **реакции** 🔥 😢 🤔 😴 — настроение, а не «нравится»: 😴 и 😢 — точно не лайк;
- **отметки** «посмотреть позже» / «просмотрено» — статус, а не отношение;
- **«Следить»** (`interest`) — подписка на новости, тоже не про «нравится».

Нажать одну кнопку и сказать «зашло» — нечем. Между тем ровно это уже работает у
подборок, людей и профилей (`PUT /social/collections/{id}/like`, `/people/{slug}/like`,
`/users/{username}/like`), и в статистике профиля есть раздел «Что нравится».

Когда делали лайки (`backend-tasks/likes.md`), решили, что у произведений их не будет:
«там оценки, отметки и реакции». На практике оказалось наоборот — оценка требует решения
(«а сколько именно?»), поэтому её ставят редко, а сердечко ставят не думая. Это два разных
сигнала, и второй заодно наполняет «Что нравится» фильмами, а не только подборками.

Сейчас `target=entity` в `/users/{username}/likes/given` принимается, но всегда пуст, а
`likes_given.entities` всегда 0 — то есть место под это в контракте уже есть.

## Что нужно

```
PUT    /api/v1/social/entities/{slug}/like   → 204
DELETE /api/v1/social/entities/{slug}/like   → 204
GET    /api/v1/social/entities/{slug}/likes  → { "likes": 128, "mine": true }
```

- Без тела: дизлайка у произведений не нужно, как и у людей (у подборок он есть, но фронтенд
  шлёт только `value: 1` — см. «Решено» в [backend-questions.md](../backend-questions.md)).
- Идемпотентно: повторный `PUT` ничего не меняет, `DELETE` без лайка — тоже 204.
- `mine` — только у вошедшего; гостю `false`. Публичное число лайков должно кэшироваться,
  личное — отдельным полем или отдельным запросом, как везде.
- 404, если произведения нет; 409 `not_released` **не нужен**: понравиться может и трейлер,
  это не оценка.

## Что должно подхватиться само

1. `likes_count` в `RatingSummary` (`GET /social/entities/{slug}/rating`) — фронтенд уже
   читает эту сводку на карточке, тогда лайк не потребует второго запроса;
2. `target=entity` в `/users/{username}/likes/given` начинает отдавать произведения, а
   `likes_given.entities` — реальное число (сейчас всегда 0);
3. `LikeTarget` с `kind: "entity"` и полем `entity: EntityRef` — для ленты «Что нравится».

## Что фронтенд включит после

| Поле / эндпоинт                 | Что появится                                           |
| ------------------------------- | ------------------------------------------------------ |
| `PUT/DELETE …/like`             | сердечко в шапке карточки, рядом с «Оценить»           |
| `likes_count` в `RatingSummary` | счётчик у сердечка без лишнего запроса                 |
| `target=entity` в likes/given   | фильтр «Произведения» в разделе профиля «Что нравится» |

После слияния: `pnpm api:types`, затем `pnpm verify`.
