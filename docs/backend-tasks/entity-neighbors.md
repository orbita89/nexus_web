# Соседи работы в выдаче (задача бэкенду)

На карточке картины есть листание: следующая работа — из того списка, откуда человек пришёл
(страница художника, тег, раздел, музей, поиск). Сейчас фронт держит ряд сам
(`src/lib/catalog/row.ts`): запоминает показанные slug'и в `sessionStorage`, а когда они кончаются
— дочитывает следующую страницу через `GET /api/v1/catalog/search` с теми же фильтрами.

Это работает, но тянет по 24 карточки ради двух соседей и ломается там, где список начался не с
начала: если человек открыл 300-ю работу со страницы 13, в запомненном ряду её может не быть
вовсе, и листание молча уходит в «Похожие».

## Что нужно

`GET /api/v1/catalog/entities/{slug}/neighbors` — соседи работы в той же выдаче, что отдаёт
`GET /search`, с теми же фильтрами:

| Параметр          | Смысл                                                           |
| ----------------- | --------------------------------------------------------------- |
| `person` + `role` | работы человека в этой роли (`role=artist` — картины художника) |
| `tag`             | работы с тегом или жанром                                       |
| `museum`          | собрание музея                                                  |
| `kind`            | тип работы (можно несколько, как в `/search`)                   |
| `sort`            | тот же порядок, что у списка; не передан — по релевантности     |

Ответ:

```json
{
	"prev": { "...": "EntitySummary" },
	"next": { "...": "EntitySummary" },
	"index": 13,
	"total": 142
}
```

- `prev` / `next` — `null` на краях ряда.
- `index` — место работы в выдаче с нуля; `total` — длина ряда. По ним фронт пишет «14 из 142».
- Работы нет в выдаче (фильтры ей не подходят) — 404 или `{prev: null, next: null, index: null}`,
  на ваше усмотрение; фронт тогда покажет «Похожие».
- Гостю доступно, кэшируемо (`s-maxage`), как и `/search`.

## Сложность, о которой стоит подумать заранее

У Meilisearch нет «дай индекс документа в выдаче»: чтобы узнать `index`, придётся либо
пагинировать выдачу до нужного документа, либо держать порядок где-то ещё. Если точный `index`
дорог — лучше отдать только `prev`/`next` и `total`, без `index`: фронту этого достаточно для
листания, счётчик «14 из 142» тогда просто не покажем. Выбор за вами, напишите, что дешевле.

## Что получит фронт

- Один маленький ответ вместо страницы карточек.
- Ряд любой длины: человек листает с 300-й работы так же, как с первой.
- Порядок гарантированно совпадает со списком, из которого пришли, — сейчас это обеспечивается
  тем, что фронт повторяет те же параметры, и ломается, если выдача успела измениться.

Интерфейс от перехода на ручку не изменится: `ArtNav.svelte` просто перестанет собирать ряд сам.
