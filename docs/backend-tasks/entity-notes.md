# Личная заметка о произведении

Сейчас всё, что человек пишет о фильме, — публично: рецензия (`PUT
/social/entities/{slug}/review`) попадает в ленту карточки, в профиль автора и в общую ленту.
Написать «для себя» нечего: ни «посмотреть вторую часть перед этой», ни «мама советовала»,
ни черновик мысли, которую не хочется показывать.

Нужна **личная заметка** — отдельная запись, которую не видит никто, кроме автора. Не флаг
приватности у рецензии: рецензия и заметка — разные вещи, и человек должен мочь иметь обе
(публичный отзыв и свою пометку).

**Оценка остаётся публичной.** Балл 1–10 по-прежнему живёт в рецензии, идёт в среднюю оценку
и в статистику профиля; заметка на него не влияет вообще.

## Эндпоинты

```
GET    /api/v1/social/entities/{slug}/note     → 200 Note | 404 (заметки нет)
PUT    /api/v1/social/entities/{slug}/note     {"body": "…"} → 200 Note
DELETE /api/v1/social/entities/{slug}/note     → 204
GET    /api/v1/social/users/me/notes?limit=&offset=  → Page<NoteWithEntity>
```

```jsonc
// Note
{
	"id": "…",
	"body": "Пересмотреть перед второй частью",
	"created_at": "2026-11-04T12:00:00Z",
	"updated_at": "2026-11-04T12:00:00Z"
}
// NoteWithEntity — то же плюс entity: EntityRef (для списка в профиле)
```

- **Только автор.** Все четыре эндпоинта — с токеном; чужую заметку нельзя получить ничем,
  включая админские ручки, и в выдачу `/users/{username}/reviews`, ленту `/social/feed`,
  `/entities/{slug}/reviews` заметки не попадают никогда.
- Одна заметка на пару «человек + произведение»: `PUT` создаёт или заменяет целиком.
- Длина текста — как у рецензии, 10 000 символов; пустой текст — 400 (чтобы удалять через
  `DELETE`, а не пустым `PUT`).
- `GET …/notes` — свой список, новые сверху, с `entity` у каждой: по нему строится вкладка
  «Заметки» в профиле. Чужой `/users/{username}/notes` **не нужен** — его не должно быть.
- 404 на `GET`, когда заметки нет (как у `…/review`) — фронтенд это уже умеет.
- В `ProfileStats` пригодится `notes` (сколько своих заметок) — показываем только себе.

## Чего делать не надо

- Не добавлять видимость к рецензии: «приватная рецензия» смешала бы два разных смысла в одной
  записи, а человеку нужно и то и другое одновременно.
- Не считать заметки в `reviews_count`, в репутацию и в ленту: это не публикация.
- Не хранить заметки в тех же таблицах, где публичные тексты, если это усложнит выдачу: лучше
  отдельная таблица `entity_notes` с уникальным ключом (user_id, entity_id).

## Что фронтенд включит после

| Бэкенд                   | Фронтенд                                                               |
| ------------------------ | ---------------------------------------------------------------------- |
| `GET/PUT/DELETE …/note`  | блок «Моя заметка» на карточке: видна только автору, рядом с рецензией |
| `GET /users/me/notes`    | вкладка «Заметки» в своём профиле — список со ссылками на произведения |
| `notes` в `ProfileStats` | число заметок в своей статистике                                       |

После слияния: `pnpm api:types`, затем `pnpm verify`.
