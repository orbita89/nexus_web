# Карточка произведения: реакции любым эмодзи и счётчик обсуждения

Две задачи про социальный слой карточки. Третья, рядом, — сердечко «нравится»:
[entity-likes.md](entity-likes.md).

## 1. Реакции — любым эмодзи, а не четырьмя

Сейчас `ReactionKind` — закрытый enum из четырёх: `fire`, `sad`, `think`, `bored`
(🔥 😢 🤔 😴). Этого мало: люди хотят ответить «❤️», «🤯», «😂», «👎», «🎬» — и видеть,
что выбрали другие. Четыре зашитые кнопки не покрывают ни один фильм целиком и выглядят
как опрос, а не как разговор.

Просьба сделать как в Slack или Discord: реакция — **строка с эмодзи**, набор не ограничен,
на карточке видно те, что уже поставили, с числом, и кнопку «+» для своей.

```
PUT    /api/v1/social/entities/{slug}/reaction   {"emoji": "❤️"}   → 204
DELETE /api/v1/social/entities/{slug}/reaction   {"emoji": "❤️"}   → 204
GET    /api/v1/social/entities/{slug}/reactions
  → { "items": [ { "emoji": "🔥", "count": 128, "mine": true },
                 { "emoji": "❤️", "count": 54,  "mine": false } ] }
```

- **Можно несколько разных** реакций от одного человека (сейчас реакция одна и заменяется) —
  иначе «+» теряет смысл: поставить ❤️ и 😂 одновременно должно быть можно. Повторный `PUT`
  того же эмодзи ничего не меняет, `DELETE` снимает конкретный.
- **Проверка значения на бэкенде**: одна графемная последовательность Unicode из категории
  Emoji (с модификаторами тона и ZWJ-последовательностями), не длиннее ~16 байт. Не эмодзи
  (буквы, цифры, разметка) — 400 с кодом `bad_emoji`. Иначе поле станет свалкой текста.
- **Порядок в ответе**: по убыванию `count`, при равенстве — кто раньше появился. Фронтенд
  показывает первые 8–10 и «ещё N».
- **Лимит на произведение**: разумно ограничить число _разных_ эмодзи у одной сущности
  (скажем, 30) — когда предел достигнут, новые принимаются только из уже существующих, иначе
  строка реакций превращается в ленту.
- `reactions` в `RatingSummary` сейчас объект с четырьмя обязательными ключами. Менять его
  ломающе — лучше добавить рядом `reaction_items: [{emoji, count}]`, а старое поле оставить
  (фронтенд перейдёт на новое, старое потом уберёте).
- Миграция: четыре нынешних вида превратить в эмодзи `🔥 😢 🤔 😴`, чтобы ничего не потерялось.
- События реалтайма: `entity.reacted` в канал `entity:{slug}` — счётчик меняется у всех
  открытых карточек без перезагрузки (как уже сделано для рецензий).

## 2. Счётчик сообщений в комнате произведения

`GET /social/chat/entity/{slug}` (`ChatRoomInfo`) отдаёт `last_message`, но **не отдаёт,
сколько всего сообщений**. У пользовательских комнат (`CustomRoom`) есть и `messages_count`,
и `messages_24h`, и `members_count` — у комнаты произведения ничего этого нет.

Из-за этого на карточке кнопка «Открыть чат» всегда выглядит одинаково: и когда там 400
сообщений, и когда пусто. А это главный признак, что произведение **обсуждают**.

Просьба: в `ChatRoomInfo` (для всех видов комнат, не только `custom`) — те же три числа:

```jsonc
{
  "room": "entity:avatar-fire-and-ash-2025",
  "kind": "entity",
  "messages_count": 412,   // всего
  "messages_24h": 37,      // за сутки — «обсуждают сейчас»
  "members_count": 58,     // кто в комнате
  "last_message": { … }
}
```

- Публично и без токена (кнопка нужна и гостю), кэшируемо.
- Если считать на лету дорого — те же счётчики, что у `CustomRoom`, пусть живут и здесь.

Пригодится не только карточке: с этим же полем страница тега и человека смогут показывать,
где идёт разговор.

## Что фронтенд включит после

| Бэкенд                            | Фронтенд                                                               |
| --------------------------------- | ---------------------------------------------------------------------- |
| `reaction_items` + `PUT {emoji}`  | строка реакций со счётчиками и кнопка «+» с палитрой эмодзи            |
| несколько реакций от одного       | снятие своей реакции повторным нажатием, несколько разных одновременно |
| `entity.reacted` в реалтайме      | счётчики меняются у всех, кто открыл карточку                          |
| `messages_count` / `messages_24h` | число на кнопке «Открыть чат» и пометка «обсуждают сейчас»             |

После слияния: `pnpm api:types`, затем `pnpm verify`.
