# Особые коллекции: читаемый URL (задача бэкенду)

Сейчас особая коллекция открывается по `/collections/{uuid}`. Для SEO нужен
человекочитаемый адрес в том же разделе: `/collections/russian-top-2021`.
Префикс `/top` не используем — особая коллекция не всегда рейтинг.
Обычные пользовательские коллекции остаются на `/collections/{uuid}`.

## Поле Collection

`slug: string | null` — во всех ответах с Collection (`/collections`,
`/collections/{id}`, `/collections/featured`, `/users/{u}/collections`,
`/entities/{slug}/collections`, лента).

- Есть только у особых коллекций, у остальных `null`.
- Уникален среди всех коллекций, включая исторические slug (см. ниже).
- Формат: `^[a-z0-9]+(-[a-z0-9]+)*$`, длина 3–100.
- Не может иметь формат UUID и не может быть зарезервированным словом:
  `featured`, `new`, `by-slug`, `admin` (список держать на бэкенде).

## Задание slug

`PUT /api/v1/social/admin/collections/{id}/featured`, тело
`{ "position"?: number, "slug"?: string }`.

- `slug` не передан при первой пометке — сгенерировать транслитом из title
  (`Русский топ 2021` → `russkiy-top-2021`), при коллизии добавить `-2`, `-3`.
- `slug` не передан при повторном PUT (смена позиции) — не менять.
- Смена slug: старый сохраняется в истории (таблица
  `collection_slug_history(slug PK, collection_id, created_at)`).

Ошибки (формат как у остальных: `{error, code}`):

| Случай                                                  | Код              |
| ------------------------------------------------------- | ---------------- |
| Неверный формат / UUID / зарезервированное слово        | 400 `validation` |
| Slug занят другой коллекцией (текущий или исторический) | 409 `conflict`   |
| Коллекция приватная                                     | 400 (как сейчас) |

`DELETE .../featured` — slug переносится в историю, у коллекции становится
`null`; занять его другой коллекцией нельзя, чтобы старые ссылки не вели на
чужой контент.

## Чтение по slug

`GET /api/v1/social/collections/by-slug/{slug}` — доступен гостю.

| Ситуация                                                    | Ответ                                            |
| ----------------------------------------------------------- | ------------------------------------------------ |
| Текущий slug особой коллекции                               | 200 `CollectionDetail` (как `/collections/{id}`) |
| Исторический slug, коллекция всё ещё особая                 | 200 `{ "redirect_slug": "<текущий>" }`           |
| Исторический slug, коллекция больше не особая, но публичная | 200 `{ "redirect_id": "<uuid>" }`                |
| Коллекция удалена / приватная / slug неизвестен             | 404                                              |

Отдельный путь `by-slug` нужен, чтобы не конфликтовать с `/collections/{id}`
(UUID) и `/collections/featured`.

## Готово, когда

- Поле `slug` и эндпоинт описаны в `documents/api/social.json`.
- Миграция с уникальным индексом и таблицей истории.
- Тесты: генерация транслита, коллизии, 400/409, редиректы по истории,
  снятие из особых.

## Фронт после реализации

- Перегенерировать `src/lib/api/generated/social.ts`.
- `buildFeaturedUrl` (`src/lib/social/featured.ts`) → `/collections/{slug}`,
  если slug есть; от него уже строятся canonical, og:url, JSON-LD, sitemap
  и ссылки в карточках.
- Роут `src/routes/collections/[id]/+page.ts`: параметр-UUID → как сейчас,
  но если коллекция особая и есть slug — 301 на `/collections/{slug}`;
  иначе запрос `by-slug` и 301 по `redirect_slug` / `redirect_id`.
- Поле slug (с автоподстановкой транслита) в `FeaturedAdminControls.svelte`,
  обработка 409 «Такой адрес уже занят».
