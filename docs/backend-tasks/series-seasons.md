# Сезоны и серии сериалов (задача бэкенду)

Сейчас сериал — одна сущность, а от сезонов в `SeriesMetadata` только два числа: `seasons: 4` и
`episodes: 32`. Показать на странице нечего: ни списка сезонов, ни серий, ни отдельной оценки
сезона. При этом люди оценивают сериалы именно по сезонам («первый — шедевр, третий — мимо»), и
единственная общая оценка на весь «Аркейн» эту разницу стирает.

Нужна страница сериала с переключателем сезонов и списком серий внутри сезона — и под это
данные.

**Видео у нас нет и не будет.** Серия — это карточка с названием, датой и длительностью, а не
плеер. Поэтому ничего про «просмотрено», прогресс просмотра, позицию в серии и «продолжить
смотреть» делать не надо: таких полей в ответах быть не должно, даже на будущее.

## 1. Сезон — сущность со своим slug

Главное решение, от которого зависит всё остальное: **сезон адресуемый, у него есть собственный
`slug` и собственная строка в той же таблице сущностей**, что фильмы и сериалы, с новым
`EntityKind` — `season`.

Почему так, а не вложенным объектом внутри сериала: оценка, рецензия, лайк, «буду смотреть»,
подборки, комментарии, ветки обсуждения, жалобы — всё это уже умеет работать с `{slug}` в
`/api/v1/social/entities/{slug}/...`. Если сезон — сущность, оценка сезона и рецензия на сезон
появляются без единой новой социальной ручки. Если сезон — вложенный объект, под него придётся
дублировать весь социальный слой во второй раз, с отдельным хранением голосов и отдельной
модерацией.

Слаг: `arcane-season-2` (`{slug сериала}-season-{n}`), генерится при создании, дальше живёт
самостоятельно и не меняется при переименовании сериала.

Поля сезона (`SeasonMetadata`, рядом с `SeriesMetadata`):

| Поле              | Тип            | Смысл                                               |
| ----------------- | -------------- | --------------------------------------------------- |
| `series_slug`     | `string`       | родительский сериал, обязателен                     |
| `number`          | `int32`        | номер сезона, 0 — спецвыпуски                       |
| `title`           | `string?`      | своё название сезона, если есть («Аркейн: Сезон 2») |
| `original_title`  | `string?`      | `Arcane: Season 2`                                  |
| `overview`        | `string?`      | описание сезона, до 2000 символов                   |
| `premiere_date`   | `date?`        | дата выхода первой серии                            |
| `finale_date`     | `date?`        | дата выхода последней вышедшей серии                |
| `episode_count`   | `int32`        | сколько серий в сезоне                              |
| `status`          | `SeriesStatus` | `ongoing` / `ended` / `canceled`, как у сериала     |
| `cover_url` и пр. | как у сущности | постер сезона                                       |

Остальное (рейтинг, лайки, оценка зрителя) приходит теми же полями, что у любой сущности —
отдельных «сезонных» форматов не заводим.

Сезоны в общий `/search` и в каталог **не попадают**: в выдаче раздела «Сериалы» должен быть
«Аркейн», а не «Аркейн, сезон 1», «Аркейн, сезон 2». Либо отдельный индекс, либо фильтр по
`kind != season` по умолчанию. Но по прямому slug'у сезон открывается и индексируется поисковиками
(своя страница, своя микроразметка).

## 2. Ручки

### `GET /api/v1/catalog/entities/{slug}/seasons`

Список сезонов сериала — то, чем рисуется переключатель `Весь сериал · 1 сезон · 2 сезон`.

```json
{
	"items": [
		{
			"slug": "arcane-season-2",
			"number": 2,
			"title": "Сезон 2",
			"premiere_date": "2024-11-09",
			"episode_count": 6,
			"status": "ended",
			"cover_url": "...",
			"rating": { "value": 9.2, "count": 420 },
			"my_rating": 10
		}
	]
}
```

- Порядок — по `number`, спецвыпуски (0) в конце.
- `rating` и `my_rating` — те же поля и та же семантика, что у сущности в карточке; гостю
  `my_rating: null`.
- Одним запросом на всю шапку: на каждой таблетке сезона сразу видно `9.5 ★ · 6 серий`, второго
  запроса на рейтинги быть не должно.
- Гостю доступно, кэшируемо (`s-maxage`), как `/search`.

### `GET /api/v1/catalog/seasons/{slug}`

Карточка сезона целиком: все поля из таблицы выше плюс `series` (краткая карточка сериала, чтобы
нарисовать шапку и хлебные крошки) и список серий.

### `GET /api/v1/catalog/seasons/{slug}/episodes`

Серии сезона, обычная страница с `limit`/`offset` (дефолт 50 — в сезоне редко больше):

```json
{
	"items": [
		{
			"id": "...",
			"number": 1,
			"title": "Тяжёлые времена",
			"original_title": "Welcome to the Playground",
			"overview": "...",
			"air_date": "2024-11-09",
			"runtime_minutes": 42,
			"still_url": "...",
			"still_width": 1280,
			"still_height": 720,
			"rating": { "value": 9.1, "count": 38 }
		}
	],
	"total": 6,
	"limit": 50,
	"offset": 0
}
```

- `rating` у серии — если считать по сериям дёшево; если нет, отдавайте `null`, карусель
  переживёт. **Оценка сезона важнее оценки серии.**
- Серия — не сущность: своего slug'а, рецензий и подборок у неё нет. Если позже захотим
  обсуждение отдельных серий — поднимем её до сущности тем же способом, что сезон, но не сейчас.
- Серии, которые ещё не вышли (`air_date` в будущем), отдавайте тоже: карусель покажет их
  неактивными с датой.

#### Кадр серии — обязательное поле, не «если будет»

Карточка серии в карусели — это в первую очередь картинка; без неё остаётся серый прямоугольник
с номером, и весь блок разваливается. Поэтому:

- `still_url` — **кадр из серии, 16:9, не постер сериала и не постер сезона.** В TMDB это
  `still_path` у эпизода, он есть почти у всех вышедших серий.
- `still_width` / `still_height` — пиксели исходника, как `cover_width` / `cover_height` в
  [задаче про размеры обложки](cover-size.md). Нужны, чтобы карточка держала точное
  `aspect-ratio` до загрузки и карусель не дёргалась при прокрутке.
- Кадра нет (серия не вышла, источник не отдал) — `still_url: null`, и тогда **подставьте
  постер сезона, а если и его нет — постер сериала**, но отдельным полем, чтобы фронт знал, что
  это заглушка, а не кадр. Проще всего так: `still_url: null` + уже приходящий `cover_url`
  сезона, подстановку сделает фронт. Молча класть постер в `still_url` не надо — пропорции
  другие (2:3 против 16:9), карточка поедет.
- Размеры — один раз при импорте, рядом с url; пересчитывать на запрос не нужно.

#### Мета серии

Минимум, без которого карточка неполная: `number`, `title`, `air_date`, `runtime_minutes` — это
ровно то, что стоит на карточке в макете («3. Сражайся или беги · 9 ноября 2024 · 45 мин»).
`original_title` и `overview` — для страницы сезона и тултипа; `overview` до 2000 символов,
обрезать на бэке не надо, фронт сам покажет сколько влезет.

`runtime_minutes` — целые минуты. Если источник отдаёт длительность в секундах, округляйте
при импорте, а не на каждом запросе.

### Социальное — ничего нового

Оценка сезона, рецензия на сезон, лайк, «буду смотреть», добавление в подборку — это уже
существующие `/api/v1/social/entities/{slug}/rating`, `/review`, `/like`, `/mark`, `/collections`
с `slug` сезона. Ничего дописывать не нужно — ровно ради этого сезон и сделан сущностью.

Единственное, о чём просим подумать: **рейтинг сериала и рейтинги сезонов не должны
перемешиваться.** Оценка сериала целиком — отдельный голос, не среднее по сезонам. Человек может
поставить 10 сериалу, 9.5 второму сезону и ничего не ставить первому; на карточке сериала в
каталоге должна оставаться оценка сериала.

## 3. Админка

`EntityForm` уже редактирует `SeriesMetadata`. Нужно:

- Создание сезона у сериала: номер, название, описание, даты, постер; slug генерится, но его
  видно и можно поправить до публикации.
- Редактирование серий сезона списком — номер, название, оригинальное название, описание, дата,
  длительность, кадр. Массовая заливка серий из импорта (TMDB отдаёт сезон целиком) важнее
  ручного ввода: на сезон из 22 серий руками никто не пойдёт.
- Удаление сезона — вместе с сериями; сезон с оценками и рецензиями не удаляется молча (как
  удаление любой сущности с социалкой).

## 4. Импорт

Сезоны и серии почти всегда приходят из внешнего источника. У TMDB это `GET /tv/{id}/season/{n}`
— один запрос отдаёт сезон и все его серии с названиями, датами, длительностями и кадрами.
Если импорт сериалов уже есть — расширьте его: при заведении сериала сразу заводятся сезоны и
серии, при обновлении подтягиваются новые серии вышедшего сезона.

Без импорта задача наполовину бессмысленна: данные руками никто не введёт.

## Что получит фронт

- Переключатель сезонов в шапке сериала с рейтингом и числом серий на каждой таблетке — один
  запрос `/seasons`.
- Карусель серий под описанием — `/seasons/{slug}/episodes`.
- Карточка сезона справа с оценкой и кнопкой «Написать рецензию на сезон» — существующие
  социальные ручки по slug'у сезона, без нового кода на бэке.
- Отдельная страница сезона `/series/arcane/season-2` (SSR, своя микроразметка) — трафик из
  поиска по запросам вида «аркейн 2 сезон», которого сейчас нет совсем.

## Что НЕ делаем

- Никакого «просмотрено», прогресса, `watched`, `progress_seconds`, «продолжить смотреть» — видео
  нет, и статус просмотра серии нам нечем заполнять.
- Серии не адресуемые, рецензий на серию нет.
- Сезоны не лезут в общую выдачу каталога.
