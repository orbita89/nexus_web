# Область поиска: несколько типов и коллекции (задача бэкенду)

Поиск на главной (`HeroSearch.svelte`) даёт выбрать, где искать: чипы «Фильмы · Сериалы ·
Книги · Игры · Люди». Ничего не выбрано — ищем везде. Сейчас выбор строго один, потому что
`GET /api/v1/catalog/search` принимает ровно один `kind`, а поиска по коллекциям нет вовсе.
Нужны две вещи.

## 1. Несколько типов разом

`GET /api/v1/catalog/search?kind=movie&kind=game` — повторяющийся параметр (или
`kind=movie,game`, на ваш выбор; фронту удобнее повторяющийся). Семантика: **ИЛИ** внутри
`kind`, **И** с остальными фильтрами (`tag`, год, `studio`, `person`, `award` — как сейчас).

- Один `kind` работает по-прежнему — ломать существующие вызовы не нужно.
- Без `kind` — все типы, как сейчас.
- Неизвестное значение — 400, как сейчас.
- Ранжирование общее по всей выдаче: не группировать по типам.

Зачем: «фильмы и игры, книги не предлагать» — частый случай, когда человек ищет по вселенной
(Fallout, «Ведьмак»), а не по одному носителю. Сейчас такой запрос приходится делать двумя
обращениями и склеивать на фронте, теряя порядок релевантности.

Фронт после этого: чипы станут переключателями с мультивыбором, в адресе —
`/search?q=…&kind=films&kind=games`.

## 2. Поиск по коллекциям

`GET /api/v1/social/collections?q=…` — полнотекстовый поиск по публичным коллекциям
(название, описание), с опечатками, та же страница `Page_Collection`, что и сейчас.

- Без `q` — поведение не меняется (новые публичные).
- Приватные и чужие не показываются; особые (`is_featured`) — показываются.
- Сортировка по релевантности; при равенстве — свежие выше.
- Индекс — Meilisearch (как каталог): поиск по подстроке в PostgreSQL для этого не годится
  (см. `docs/README.md`).

Коллекции — **отдельная область**: вместе с произведениями в одной выдаче они не ищутся, это
осознанно (разные сущности, разные карточки). На фронте это будет чип «Коллекции», который
снимает выбор типов, и наоборот.

## Что не нужно

Общий поиск «по всему сайту» (произведения + люди + коллекции + темы форума одним запросом) —
не нужен. Фронт сам дёргает две-три ручки параллельно и показывает блоками.
