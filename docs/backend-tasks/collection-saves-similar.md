# Избранные и похожие подборки (задача бэкенду)

Две вещи для страницы коллекции (в первую очередь особой подборки):

1. **Избранное** — кнопка-закладка «Добавить в избранное» у названия; список
   сохранённых подборок в профиле. Сейчас сохранять можно только отметки
   произведений (`/entities/{slug}/mark`, `/users/me/marks`), коллекции — нельзя.
2. **Похожие подборки** — блок внизу страницы. Эндпоинта нет; фронт временно
   ранжирует список `/collections/featured` сам (по превью и теме), что грубо.

## Избранное

### PUT /api/v1/social/collections/{id}/save

- Добавить в избранное. **204**, идемпотентно (повтор — тоже 204).
- Только вошедший: без токена — **401**.
- Чужая приватная (или нет такой) — **404**. Своя приватная — можно.

### DELETE /api/v1/social/collections/{id}/save

- Убрать из избранного. **204**, идемпотентно (не было — тоже 204). 401/404 — как у PUT.

### Поля коллекции

В `Collection` / `CollectionDetail` (во всех ответах: список, детальная,
`/collections/featured`, by-slug, лента):

| поле          | тип     | примечание                                       |
| ------------- | ------- | ------------------------------------------------ |
| `is_saved`    | boolean | в избранном у смотрящего; гостю всегда `false`   |
| `saves_count` | integer | сколько пользователей сохранили (публичный счёт) |

Ответы с `is_saved` персональные — особую подборку фронт кэширует на CDN
(рендер как для гостя), поэтому для гостя поле должно быть стабильно `false`,
а для вошедшего фронт перечитывает коллекцию в браузере.

### GET /api/v1/social/users/me/saved-collections

- Только вошедший (401). `Page_Collection`: `{ items, total, limit, offset }`.
- `limit` (1–100, по умолчанию 20), `offset`.
- Порядок: **недавно сохранённые сверху** (по времени сохранения, затем `id`).
- Ставшие приватными чужие коллекции и удалённые — не возвращать (сохранение
  удалённой — каскадом удалить).
- Публичный `/users/{username}/saved-collections` пока **не нужен** — избранное
  видно только владельцу.

## Похожие подборки

### GET /api/v1/social/collections/{id}/similar?limit=6

- Публичный, гостю можно. `limit` 1–24, по умолчанию 6. Ответ — `Collection[]`
  (без пагинации).
- Только **публичные** коллекции, сама коллекция исключена. Источник —
  публичная или своя приватная (чужая приватная — 404).
- Ранжирование:
  1. пересечение произведений — Jaccard по множествам `entity_id` пунктов;
  2. затем общие теги/жанры произведений (доля совпадений);
  3. затем та же `theme`;
  4. особые (`is_featured`) — с бонусом; при равенстве — по `featured_position`,
     потом свежие.
- Если похожих мало — добивать особыми подборками по `featured_position`, чтобы
  блок не был пустым.
- Кэшируемо: `Cache-Control: public, s-maxage=600` (ответ не персональный).

## Фронт после реализации

- Перегенерировать типы API ( `src/lib/api/generated/social.ts`).
- Избранное: `SAVES_SUPPORTED = true` в `src/lib/social/collections.ts`, убрать
  приведения типов в `isSaved` / `setCollectionSaved`. Кнопка
  `src/lib/components/social/SaveCollectionButton.svelte` уже стоит у названия в
  `FeaturedCollectionView.svelte` (рядом с «Поделиться»). Для вошедшего
  `is_saved` берётся из перечитанной в браузере коллекции.
- Профиль: вкладка «Избранное» только на своём профиле —
  `src/routes/u/[username]/saved/+page.ts` + `+page.svelte` (список карточек как
  в `src/routes/u/[username]/collections/+page.svelte`, «Показать ещё» по
  `offset`), пункт в `tabs` в `src/routes/u/[username]/+layout.svelte` при
  `username === session.user`; чужому — 404/редирект на профиль.
- Похожие: в `src/routes/collections/[id]/+page.ts` заменить `getFeaturedCollections`
  - `rankSimilar` (`src/lib/social/featured.ts`) на `/collections/{id}/similar`;
    `rankSimilar` и его тест удалить.
