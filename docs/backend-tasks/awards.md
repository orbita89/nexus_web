# Награды (задача бэкенду)

Нужен раздел «Награды»: вкладка в шапке, список премий с разбивкой по типам работ
(фильмы, сериалы, книги, игры), внутри премии — годы (церемонии), внутри года —
номинации по категориям с победителями, работами и людьми.

Сейчас на бэкенде наград как сущности нет. В `EntityDetail.metadata.awards` лежит
плоский список строк:

```json
{ "title": "«Оскар» за лучшую операторскую работу", "year": 2022, "won": true }
```

По нему можно нарисовать строчки в блоке «Производство и факты» на карточке — и всё.
Собрать из него страницу «Оскар 2024» нельзя: нет самой премии как объекта, нет
категорий, нет связи номинации с человеком, нет обратного обхода «все работы премии».
Разбирать строки регулярками на фронте — не вариант: по
[правилу проекта](../architecture.md) любые выборки и фильтрация идут через Meilisearch,
а не через клиентскую эвристику.

## Модель

### `awards` — премия

| Колонка       | Тип                               | Примечание                          |
| ------------- | --------------------------------- | ----------------------------------- |
| `id`          | uuid                              |                                     |
| `slug`        | text, unique                      | `oscar`, `the-game-awards`, `hugo`  |
| `title`       | text                              | «Оскар»                             |
| `full_title`  | text, null                        | «Премия Американской киноакадемии»  |
| `kinds`       | text[]                            | `movie`, `series`, `book`, `game`   |
| `country`     | text, null                        | «США»                               |
| `founded`     | int, null                         | год учреждения                      |
| `description` | text, null                        | 1–2 абзаца на страницу премии       |
| `logo_url`    | text, null                        | логотип/статуэтка                   |
| `site_url`    | text, null                        | офсайт                              |
| `position`    | int                               | ручной порядок в списке, крупные выше |

`kinds` — массив, а не одно значение: у «Золотого глобуса» и фильмы, и сериалы.
Разделение в UI идёт по нему (вкладки «Фильмы / Сериалы / Книги / Игры»).

### `award_editions` — церемония (премия + год)

| Колонка    | Тип                          | Примечание                          |
| ---------- | ---------------------------- | ----------------------------------- |
| `id`       | uuid                         |                                     |
| `award_id` | uuid, FK → awards, CASCADE   |                                     |
| `year`     | int                          | год церемонии, 1880–2100            |
| `number`   | int, null                    | «96-я церемония»                    |
| `held_on`  | date, null                   | дата проведения                     |
| `place`    | text, null                   | «Dolby Theatre, Лос-Анджелес»       |
| `cover_url`| text, null                   | фон/постер церемонии                |

Unique `(award_id, year)`. Год церемонии и «год фильмов» часто разные (Оскар 2024 —
за 2023-й): если это важно, добавьте `season_year int, null`, фронт покажет
«за 2023 год».

### `award_categories` — категория

| Колонка    | Тип                        | Примечание                                  |
| ---------- | -------------------------- | ------------------------------------------- |
| `id`       | uuid                       |                                             |
| `award_id` | uuid, FK → awards, CASCADE | категории принадлежат премии, не церемонии  |
| `slug`     | text                       | `best-picture`                              |
| `title`    | text                       | «Лучший фильм»                              |
| `position` | int                        | порядок на странице церемонии               |

Unique `(award_id, slug)`. Категории меняются по годам (появляются, исчезают,
переименовываются) — поэтому они привязаны к премии, а что именно было в конкретном
году, видно по номинациям этой церемонии. Если переименование нужно хранить точно,
достаточно `title_override` в номинации.

### `award_nominations` — номинация

| Колонка       | Тип                                    | Примечание                            |
| ------------- | -------------------------------------- | ------------------------------------- |
| `id`          | uuid                                   |                                       |
| `edition_id`  | uuid, FK → award_editions, CASCADE     |                                       |
| `category_id` | uuid, FK → award_categories, RESTRICT  |                                       |
| `entity_id`   | uuid, FK → entities, null              | работа                                |
| `person_id`   | uuid, FK → people, null                | человек                               |
| `name`        | text, null                             | если ни того, ни другого нет в базе   |
| `role`        | text, null                             | «режиссёр», «за роль Оппенгеймера»    |
| `won`         | bool, default false                    | победитель категории                  |
| `position`    | int                                    | порядок внутри категории              |

- Хотя бы одно из `entity_id`, `person_id`, `name` заполнено (CHECK).
- Актёрские категории — это и работа, и человек сразу: оба FK заполнены, фронт
  показывает фото человека и строкой — фильм.
- Победителей в категории может быть несколько (ничья, совместные награды), поэтому
  `won` — флаг на номинации, а не `winner_id` в категории.

## Чтение (публичное, гостю доступно, кэшируемо `s-maxage=600`)

Всё под `GET /api/v1/catalog/awards`.

- `GET /awards?kind=movie&q=&page=&per_page=` → `{ items: Award[], total }`.
  `kind` — фильтр по `kinds` (он же вкладки раздела), `q` — поиск по названию.
  Хорошо бы в элементе списка отдать `editions_count` и `latest_year`, чтобы на
  плитке премии сразу было «1929–2024».
- `GET /awards/{slug}` → `AwardDetail`: поля премии + `editions: AwardEditionBrief[]`
  (год, номер, дата, обложка, `nominations_count`, `top: EntityRef[]` — 3–5 победителей
  главной категории для превью). Сортировка — год по убыванию.
- `GET /awards/{slug}/{year}` → `AwardEditionDetail`: церемония + `categories`,
  каждая — `{ slug, title, position, nominations: Nomination[] }`, номинации уже
  отсортированы (победители первыми). В `Nomination` — `entity: EntitySummary | null`
  (со `slug`, `cover_url`, `release_date` — фронту нужен постер), `person: PersonRef | null`
  (`slug`, `name`, `photo_url`), `name`, `role`, `won`.
  Год без церемонии — 404.

Этого хватает на все четыре экрана: список премий, премия → годы, год → категории,
карточка/человек как ссылка.

### Обратная сторона — награды у работы и человека

- В `EntityDetail` вместо (или рядом с) нынешних строк `metadata.awards` —
  `awards: EntityAward[]`, где `EntityAward = { award: { slug, title, logo_url },
  year, category: { slug, title }, role, won }`. Тогда блок «Награды» на карточке
  станет ссылками на `/awards/oscar/2024`, а не просто текстом.
- То же поле в профиле человека (`PersonDetail`).

Старое строковое `metadata.awards` при этом остаётся до миграции контента —
фронт отрисует новое поле, если оно есть, иначе старое.

### Meilisearch

Чтобы «фильмы с „Оскаром“» и сортировка по числу наград работали в каталоге
(правило проекта: фильтрация — только индексом), в документ работы нужны:

- `award_slugs: string[]` (`["oscar", "bafta"]`) — фильтруемое;
- `award_wins: int`, `award_nominations: int` — фильтруемое и сортируемое;
- `award_years: int[]` — фильтруемое (фасет «лауреаты 2024»).

Переиндексация — при изменении номинаций.

## Изменение (только admin)

Под `/api/v1/catalog/admin/awards`, ответы — изменённый объект, не админ — 403.

- `POST /awards`, `PATCH /awards/{slug}`, `DELETE /awards/{slug}` (каскадом сносит
  церемонии и номинации — требовать `?force=true`, иначе 409, если номинации есть);
- `POST|PATCH|DELETE /awards/{slug}/editions/{year}`;
- `POST|PATCH|DELETE /awards/{slug}/categories/{category_slug}`;
- `PUT /awards/{slug}/{year}/nominations` — заменить список церемонии целиком
  (удобно для импорта: тело `{ categories: [{ slug, nominations: [...] }] }`);
- `POST|PATCH|DELETE` одной номинации — для точечных правок.

Загрузка логотипа и обложки — через существующую загрузку картинок, в полях только URL.

Импорт исторических церемоний (Оскар с 1929-го — это тысячи строк) удобнее делать
отдельной командой на стороне бэкенда; API для этого достаточно `PUT`-а целиком.

## Что фронтенд сделает после

- вкладка «Награды» в шапке (рядом с «Люди», «Коллекции»);
- `/awards` — вкладки по типам работ и плитки премий (логотип, годы, число церемоний);
- `/awards/{slug}` — описание премии и сетка годов;
- `/awards/{slug}/{year}` — категории, в каждой победитель крупно (постер работы или
  фото человека) и остальные номинанты строками;
- блок «Награды» на карточке работы и в профиле человека — ссылками на церемонии;
- фильтр «есть награда» в каталоге — на фасетах Meilisearch.

После изменения схемы обновить `nexus_project/documents/api/catalog.json` —
фронтенд перегенерирует типы (`pnpm api:types`).
