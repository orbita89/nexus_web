# Архитектура страниц: статика, ISR и раздача

Как сайт превращает страницы каталога в готовые файлы, где они лежат, кто и как их отдаёт и как
их обновлять. Общая архитектура фронтенда — `docs/architecture.md`; здесь — только страницы.

**Главное правило.** Публичная страница каталога, открытая хоть раз, дальше отдаётся готовым
файлом с диска: без рендера, без API и без базы. Живое (оценки, рецензии, «моя оценка») браузер
догружает сам. Это одинаково в проде и в деве.

## 1. Какие страницы — статика

| Страница | Адрес | Статика | Где описана |
|---|---|---|---|
| Карточка книги | `/books/{slug}` | да, только `.br`, по папкам | `src/routes/[kind=kind]/[slug]/+page.server.ts` |
| Карточки фильма, сериала, игры, картины | `/films/{slug}`, `/series/…`, `/games/…`, `/paintings/…` | да, `.html` + `.br` + `.gz` | то же |
| Студия | `/studios/{slug}` | да | `src/routes/studios/[slug]/+page.server.ts` |
| Премия, церемония | `/awards/{slug}`, `/awards/{slug}/{год}` | да | `src/routes/awards/…` |
| Люди | `/people/{slug}` | пока нет (SSR на запрос) | следующий шаг |
| Разделы, поиск, теги, лента, профиль, админка | — | нет: зависят от фильтров или пользователя | — |

Список статических адресов задан одной регуляркой в трёх местах, их надо менять вместе:
`STATIC_PAGE` в `server/isr.js`, location в `deploy/nginx.conf` (прод) и `infra/nginx.conf`
в nexus_project (дев).

Страница может быть статикой, если она одинакова для всех: `+page.server.ts` с
`export const prerender = 'auto'`, а в `load` — только каталог.

## 2. Из чего состоит готовая страница

У каждой страницы два ресурса:

- **HTML** — для первого захода (адрес набран, переход из поиска, ссылка из мессенджера). Полная
  разметка, мета-теги и JSON-LD видны сразу — и человеку, и поисковику.
- **`__data.json`** — результат `load` (данные каталога). Нужен при переходе кликом внутри сайта:
  SvelteKit берёт только данные и рисует страницу в браузере, HTML целиком не качает. Те же данные
  встроены в конец HTML для гидрации — без них страница ждала бы лишний запрос.

### Что внутри HTML (на примере книги)

- **Минифицирован** (`minifyHtml` в `server/isr.js`, html-minifier-terser): пробелы сжаты до
  одного. Не трогаются комментарии-метки Svelte (`<!--[-->`, `<!---->`) — по ним он оживляет
  страницу — и элементы с `whitespace-pre*` (абзацы описания).
- **Без лишних данных**: из `entity` выброшены поля, которых страница не рисует (`forPage` в
  `+page.server.ts`: `libgen`, `file`, `keywords` в metadata, поля ранжирования).
- **Обложка (LCP)**: `<link rel="preload" as="image" fetchpriority="high">` в `<head>`, у `<img>`
  — `fetchpriority="high"`, `loading="eager"`, `width`/`height` из `cover_width`/`cover_height`.
  Место держит плитка с `aspect-ratio` — страница не прыгает (CLS = 0). Остальные картинки
  (`Poster` ниже сгиба, аватары) — `loading="lazy" decoding="async"`.
- **SEO**: `title`, `description`, `canonical`, `og:*` (`og:type=book`, `og:locale=ru_RU`),
  `twitter:card`, JSON-LD `schema.org/Book` (автор, ISBN, язык, страницы, издательство, серия) —
  `Seo.svelte`, `src/lib/catalog/jsonld.ts`. `lang="ru"` — в `app.html`.
- **CSS и JS — внешние файлы** с хэшем в имени (`/_app/immutable/…`), кэш навсегда.
- **Живого в HTML нет**: оценки, рецензии, обсуждения, рекомендации грузятся в браузере
  (`card-live.svelte.ts`, `ClientSection` — лениво, когда блок подходит к экрану).

Размеры (книга «Идиот», 2026-11): HTML 42 КБ → `.br` 8 КБ; `__data.json` 2,2 КБ → `.br` 1 КБ.

### Книга: кнопка «Читать»

В статику книги попадает только `metadata.file = { size }` (есть ли файл и его размер) и
`metadata.public_read` — путь к файлу в архиве вырезается (`forPage`). Что показать на кнопке
(«Читать», «Войдите, чтобы читать», «Доступ по приглашению»), решает браузер после гидрации по роли
(`ReadButton.svelte`, `src/lib/reader/access.ts`) — страница одна для всех. Читалка
`/books/{slug}/read` — не статика (`ssr = false`), книги кэшируются в IndexedDB браузера
(`src/lib/reader/cache.ts`, `open.ts`).

## 3. Где лежат файлы

Корень — `build/prerendered/` релиза (`server/index.js`: `root`).

### Книги — только сжатые и по папкам

Книг сотни тысяч, поэтому:

```
build/prerendered/books/id/idiot-litres.html.br
build/prerendered/books/id/idiot-litres/__data.json.br
```

- **Папка — первые два символа slug** (`staticFiles` в `server/isr.js`). Адрес сайта не меняется:
  `/books/idiot-litres`; папку `id/` не видит ни читатель, ни поисковик. Вычисляется из адреса без
  базы — так же в nginx (именованные захваты `$shard`, `$book`).
- **Только `.br`** (`brOnly`, `publishBrotli`): нет несжатого файла и `.gz`. 2 файла на книгу.
  Блок файловой системы — 4 КБ, поэтому на диске книга занимает ~12–16 КБ: 315 тыс. книг ≈ 4–5 ГБ.

### Остальные страницы — плоско, три варианта

```
build/prerendered/films/dune-2021.html      (+ .br, .gz)
build/prerendered/films/dune-2021/__data.json (+ .br, .gz)
```

Их тысячи — выигрыш от `.br`-only мал. Переводятся тем же способом при необходимости
(`brOnly` в `server/isr.js` и location в nginx).

## 4. Кто отдаёт страницу

```
браузер ──► nginx ──┬─ файл есть на диске ─────────────► отдаёт сам        (X-Static: nginx)
                    └─ файла нет / клиент без brotli ──► Node :3000
                                                          ├─ файл есть ───► с диска   (x-isr: hit)
                                                          └─ нет ─────────► рисует, сохраняет,
                                                                             отдаёт   (x-isr: miss)
```

### Книги

| Клиент | Кто отдаёт | Что |
|---|---|---|
| Браузер с brotli (`Accept-Encoding: br`, ~97%: Chrome, Яндекс, Safari, Firefox, Edge; встроенные браузеры Telegram/VK) | nginx с диска | `.br` как есть, `Content-Encoding: br` |
| Без brotli: старые браузеры, роботы превью ссылок, `curl`, часть ботов | Node с диска | распаковывает тот же `.br`, отдаёт HTML |

nginx не сжимает и не распаковывает: модуль brotli для книг не нужен. Выбор — без `if`:
`map $http_accept_encoding $nexus_br_suffix` даёт пустой суффикс для brotli и `.nobr` для
остальных, `try_files /books/$shard/$book.html.br$nexus_br_suffix @app` — файла `….br.nobr` нет,
и запрос уходит в Node. Ответ всегда с `Vary: Accept-Encoding`.

### Заголовки

- `Cache-Control: public, max-age=300` — 5 минут браузер берёт страницу из своего кэша, потом
  переспрашивает с ETag и получает 304. Правка карточки видна читателю не позже чем через 5 минут.
- `ETag` — время изменения и размер файла (и у nginx, и у Node).
- Проверка, откуда пришла страница:
  `curl -sI -H 'Accept-Encoding: br' https://…/books/idiot-litres | grep -i -E 'x-static|x-isr|content-encoding'`.

## 5. Как страница появляется и обновляется (ISR)

Рисует и пишет файлы только сервер фронтенда (`server/isr.js`), рендером той же сборки
SvelteKit (`server.respond`).

1. **Сборка** (`pnpm build`): `entries()` пререндерит карточки из API, **кроме книг** — их слишком
   много. С `PRERENDER_ENTITIES=0` (дев, CI) — ничего; всё рисуется по запросу. Сборка стирает
   `build/` целиком: HTML ссылается на JS своей сборки.
2. **Первый запрос** без файла → Node рисует, сохраняет, отдаёт (`x-isr: miss`). Дальше — с диска.
3. **Правка в админке** → бэкенд шлёт `POST /_isr/revalidate {"paths": [...]}` → страница
   перерисовывается до ответа. 404 или редирект (удалили, сменили раздел) — файлы удаляются.
   5xx (бэкенд лежит) — старые файлы остаются.
4. **Пересборка раздела или всего** — админка (п. 6) или `pnpm revalidate --all`.

Запись (`publish`, `publishBrotli`):

- **Атомарно**: во временный файл рядом и `rename` — nginx не увидит недописанный файл.
- **Хэш-трекинг**: новая страница сравнивается со старой (у книг — с распакованным `.br`). Совпала
  байт в байт — файл не трогается: mtime и ETag прежние, у читателей и прокси работает 304, диск
  не пишется. Пересборка показывает, сколько страниц действительно изменилось.
- **Brotli на максимум** (quality 11, режим текста): сжимаем один раз, отдаём тысячи раз.
- Старые несжатые файлы книги (раскладка до `.br`-only) удаляются при её перерисовке.

## 6. Админка: перегенерация

`/admin/books` → блок «Статические страницы книг» (`StaticPagesPanel.svelte`):

- **«Перегенерировать все книги»** (с подтверждением) → бэкенд
  `POST /api/v1/catalog/admin/static/regenerate {"kind": "book"}` → фронтенд
  `POST /_isr/revalidate {"all": true, "kind": "book"}` (202, в фоне). Список — каталог из API
  (`GET /entities?kind=book`) плюс всё, что уже лежит на диске (так уходят удалённые).
  По `ISR_CONCURRENCY` (8) страниц одновременно.
- **«Перерисовать»** одну книгу по slug или ссылке → `POST /admin/static/pages {"paths": […]}`,
  до ответа.
- **Ход** — `GET /admin/static/status` (← `GET /_isr/status`): всего, готово, изменено, ошибки
  (первые 100), начало и длительность. Опрос раз в 3 секунды, пока идёт. Ход живёт в памяти
  сервера фронтенда — после его перезапуска пустой.

Без `ISR_URL`/`ISR_SECRET` у бэкенда эндпоинты отвечают 503. Вторая пересборка, пока идёт первая,
не запускается (`started: false`).

## 7. Дев = прод

| | Прод | Дев |
|---|---|---|
| Сайт | `https://…` | `http://localhost` (не :5173) |
| nginx | `deploy/nginx.conf` на хосте, ngx_brotli | шлюз `nexus-gateway` (`infra/nginx.conf` в nexus_project), `nginx:alpine` |
| Сервер фронтенда | `node server/index.js` на 127.0.0.1:3000 | `pnpm dev` (сборка + сервер) или `pnpm serve` (без сборки) на 0.0.0.0:3000 |
| Каталог статики | `/srv/nexus-web/current/build/prerendered` | `nexus_web/build/prerendered`, в шлюзе — `/srv/nexus-web/build/prerendered` |
| Пререндер при сборке | карточки кроме книг | нет (`PRERENDER_ENTITIES=0`) |
| ISR от бэкенда | `ISR_URL`, `ISR_SECRET` в окружении | по умолчанию `http://host.docker.internal:3000`, `nexus-dev-isr-secret` |

`pnpm dev:vite` — старый режим (Vite, :5173, горячая перезагрузка) только для вёрстки: статики
там нет, каждая страница рисуется на запрос.

### Грабли дева

- Шлюз монтирует `infra/nginx.conf` **отдельным файлом**: правка, которая создаёт новый файл
  (`sed -i`, `mv`), в контейнер не попадает, а `nginx -s reload` молча применит старый конфиг.
  Проверка: `docker exec nexus-gateway grep <строка> /etc/nginx/conf.d/default.conf`; если нет —
  `docker compose -f infra/docker-compose.yml up -d --force-recreate nginx`.
- Каталог `nexus_web` монтируется в шлюз целиком, а не `build/`: сборка пересоздаёт `build/`, и
  примонтированный `build/` остался бы старым.
- Сервер фронтенда для nginx — `upstream` (разрешается при старте по `/etc/hosts`), а не
  переменная: `host.docker.internal` DNS Docker не знает.
- В nginx-регулярках location книг — именованные захваты: проверка через `map` затирает `$1`, `$2`.

## 8. Прод: что проверить при выкладке

Полная инструкция (генерация на локальной машине, выгрузка, CDN, проверка) — `docs/production.md`.

- **Окружение бэкенда**: `ISR_URL` — адрес сервера фронтенда, **достижимый из контейнера
  бэкенда** (127.0.0.1 хоста из контейнера не виден), `ISR_SECRET` — тот же, что у фронтенда.
  Без них правки в админке не обновляют страницы, а перегенерация отвечает 503.
- **`map $nexus_br_suffix`** в `deploy/nginx.conf` — на уровне `http` (файл подключается внутри
  `http {}`, как server-блок).
- **HTTPS обязателен для brotli**: браузеры просят `br` только по HTTPS (и на localhost).
- **Новый релиз** собирается с нуля — статика книг пустая и наполняется по заходам. Прогреть
  заранее — «Перегенерировать все книги»; на 315 тыс. страниц это часы: список книг из API
  постранично по offset, рендер по 8 одновременно. Оценить по первому прогону в админке.
- **Место**: `du -sh /srv/nexus-web/current/build/prerendered/books`, `df -i` (inode).

## 9. Как добавить раздел в эту схему

Например, люди (`/people/{slug}`):

1. `+page.ts` → `+page.server.ts` с `prerender = 'auto'`; в `load` — только каталог, живое
   (оценки фильмографии) — в браузер.
2. Адрес — в `STATIC_PAGE` (`server/isr.js`) и в location обоих nginx.
3. Много страниц — в `staticFiles` (папки) и `brOnly` (только `.br`), location по образцу книг.
4. Раздел — в `SECTION`/`STATIC_DIRS` (`server/isr.js`) и `KINDS` (`admin/static_pages.rs`), если
   нужна перегенерация из админки.
5. Бэкенд уже шлёт `/people/{slug}` в revalidate (`publish.rs`) — начнёт обрабатываться сам.
