# Архитектура

## Стек

|           |                                                                      |
| --------- | -------------------------------------------------------------------- |
| Фреймворк | SvelteKit 3, Svelte 5 (runes), `adapter-node`                        |
| Язык      | TypeScript strict                                                    |
| Стили     | Tailwind CSS 4 + DaisyUI 5, своя тёмная тема `nexus`. Своего CSS нет |
| API       | `openapi-typescript` (типы) + `openapi-fetch` (клиент)               |
| Проверки  | prettier, eslint, svelte-check, vitest (Node + браузер), Playwright  |
| Пакеты    | pnpm                                                                 |

Особенности SvelteKit 3, на которые легко наткнуться:

- конфиг — в `vite.config.ts` (`sveltekit({ adapter })`), `svelte.config.js` нет;
- вместо `$lib` — subpath imports: `#lib/...` **с расширением** (`#lib/api/errors.ts`);
- матчеры параметров — `src/params.ts` (`defineParams`), переменные окружения — `src/env.ts`
  (`defineEnvVars`, читаются из `$app/env/private`), `browser` — из `$app/env`;
- типы хуков — из `@sveltejs/kit/hooks`.

## Адреса

Карточка сущности — `/{раздел}/{slug}`: `/films/dune-2021`, `/books/dune`. slug уникален во всём
каталоге, раздел в адресе — для читаемости и SEO. Раздел не совпал с типом сущности — 301 на
правильный адрес (query сохраняется), неизвестный slug — 404.

| Адрес                                    | Что                                                              |
| ---------------------------------------- | ---------------------------------------------------------------- |
| `/`                                      | новинки по разделам (пустой раздел скрыт), популярные теги       |
| `/films?tag=&year=&q=&sort=&offset=`     | раздел с фильтрами и порядком (`sort`: trending, new, title…)    |
| `/films/dune-2021`                       | карточка: шапка Okko или постер, «О фильме», лента               |
| `/films/dune-2021/reviews?sort=&offset=` | все рецензии на произведение                                     |
| `/u/{username}/reviews?offset=`          | рецензии и оценки пользователя                                   |
| `/u/{username}/stats`                    | аналитика целиком: сводка, оценки, отметки, комментарии          |
| `/people?q=&offset=`, `/people/{slug}`   | люди; человек и его работы (одна карточка — все роли)            |
| `/tags`, `/tags/{slug}?kind=&offset=`    | теги; сущности с тегом, фильтр по разделу (`kind` — `films`…)    |
| `/studios/{slug}?sort=`                  | студия: шапка из TMDB и её фильмы (статика, `sort` — в браузере) |
| `/search?q=&kind=&offset=`               | поиск (Meilisearch); пустой `q` — подсказка, 503 — сообщение     |

**Состояние списков — в адресе** (`#lib/catalog/url.ts`): фильтры и страница — query-параметры,
пустые значения и `offset=0` не пишутся, смена фильтра сбрасывает страницу. Формы фильтров —
обычные `<form method="GET">`: без JS работают как есть, с JS отправка перехватывается и делается
`goto()` без пустых полей. Пагинация — ссылки `?offset=24`, страница всегда 24 элемента
(делится на 2/3/4/6 колонок). Назад/вперёд и «поделиться ссылкой» работают без доп. кода. Профиль — `/u/{username}` (как в API social:
пользователи адресуются по username).

## SSR и что где рендерится

Токены живут только в браузере (см. [auth.md](auth.md)), поэтому сервер всегда рендерит страницу
**как для гостя**:

| Что                                                               | Где                            |
| ----------------------------------------------------------------- | ------------------------------ |
| Карточка произведения (`/films/dune-2021`), студия (`/studios/…`) | статика + ISR, см. ниже        |
| Оценки, рецензии, обсуждения, «В коллекциях» на карточке          | в браузере, лениво             |
| Каталог, люди, теги, поиск, форум, публичные профили и коллекции  | SSR (SEO), публичные данные    |
| Личное на этих страницах: моя оценка, «Подписаться», «Следить»    | догружается в браузере         |
| Лента, настройки, создание темы — группа `(protected)`            | только браузер (`ssr = false`) |
| Вход, регистрация, ссылки из писем — `auth/`                      | только браузер                 |

### Карточка — статика и ISR

Карточка — `+page.server.ts` с `prerender = 'auto'`, данные — только каталог (`{ entity }`).
Серверный load, а не `+page.ts`: только у него есть `__data.json` — статический файл, который
браузер берёт при переходах вместо запросов к API. `'auto'`, а не `true`: с `true` маршрут
выпадает из серверной сборки — ни перерисовать одну карточку, ни показать новую до сборки.

- **Сборка.** `pnpm build` (и `verify`) — со статикой, e2e собирают без неё; нужен живой `BACKEND_URL`,
  для прода — `ORIGIN` (попадает в `og:url`). Без бэкенда — `PRERENDER_ENTITIES=0` (так в CI):
  `entries()` листает `GET /catalog/entities`, на каждую карточку — `films/x.html`,
  `films/x/__data.json` и их `.br`/`.gz` в `build/prerendered`. Каждая сборка стирает `build/`
  и собирает статику заново; `pnpm dev` статики не использует — там карточка рендерится на запрос.
- **Раздача.** nginx (`deploy/nginx.conf`) отдаёт карточки с диска; query не важен. Файла нет —
  запрос идёт в Node (`server/index.js`), он рисует, сохраняет и отдаёт (`x-isr: miss`); дальше
  снова с диска. Без nginx (`pnpm start` локально) готовый файл отдаёт сам Node (`x-isr: hit`, без
  бэкенда). В `pnpm dev` статики нет: страница рисуется на каждый запрос и ходит в API.
  Проверить, откуда пришла страница: `curl -sI <адрес> | grep -i -E 'x-static|x-isr'` —
  `X-Static: nginx` (с диска через nginx), `x-isr: hit` (с диска через Node), `x-isr: miss`
  (нарисована сейчас и сохранена).
- **Живое — всегда из API.** В HTML и `__data.json` только каталог. Сводка оценок, рецензии,
  обсуждения, коллекции и «Рекомендации» браузер грузит сам (5 запросов на карточку): в статике
  они бы устарели.
- **ISR.** `POST /_isr/revalidate` (`Authorization: Bearer $ISR_SECRET`) — его зовёт бэкенд
  после каждой админской правки (`ISR_URL`, `libs/shared/src/isr.rs`: таймаут 30 с, успех —
  любой 2xx). Два тела:
  - `{"paths": [...]}` (до 100) — перерисовать до ответа сборкой SvelteKit (`server.respond`) и
    атомарно заменить файлы (`server/isr.js`). 404 или редирект (удалили, сменили раздел) — файлы
    удаляются, адрес обслуживает SSR; 5xx — старые файлы остаются, ответ 502. Статические адреса —
    `STATIC_PAGE` в `server/isr.js` (карточки и `/studios/…`, те же — в `deploy/nginx.conf`);
    остальные (`/people/…`, бэкенд шлёт и их) — `skipped`.
  - `{"all": true}` — после ручной перестройки поиска: 202 сразу, в фоне перерисовываются весь
    каталог из API и всё, что лежит на диске (так уходят удалённые, студии — только с диска: списка
    студий в API нет), по `ISR_CONCURRENCY` (8).
    Вторая, пока идёт первая, не запускается. Ход и итог — в логе сервера.

  Вручную: `pnpm revalidate /films/dune-2021` или `pnpm revalidate --all` (`scripts/revalidate.mjs`).

- **Кэш в браузере — 5 минут** (`Cache-Control: public, max-age=300` у HTML и `__data.json`
  карточек и студий, `STATIC_CACHE` в `server/index.js` и `deploy/nginx.conf`): повторное открытие
  и переход на неё в эти 5 минут не идут на сервер вовсе, потом — переспрос с ETag и 304. Цена — правка карточки (ISR) видна тому, кто её недавно открывал, не сразу, а в пределах 5
  минут. Живые блоки (оценки, рецензии) не кэшируются — они из API.
- **Предзагрузка** (`src/app.html`): данные — по нажатию (`data-sveltekit-preload-data="tap"`,
  `mousedown`/касание, за 100–200 мс до перехода), код страниц — по наведению (чанки кэшируются
  навсегда). Не `hover` для данных: проход мышкой по сетке постеров запрашивал `__data.json` каждой
  карточки под курсором.
- **Деплой.** Пререндер и ISR пишут в каталог релиза: HTML ссылается на хэшированные чанки своей
  сборки, поэтому новый релиз собирается с нуля (`pnpm build`), старые файлы не переносятся. При
  выкладке прошлый релиз остаётся симлинком `previous`: nginx берёт из него `_app/immutable`, если
  в новом чанка нет, — иначе страница из кэша браузера (до 5 минут) не загрузила бы свои скрипты.

Почему свой сервер, а не `node build`: `event.fetch` к пререндеренному адресу уходит настоящим
HTTP-запросом (получил бы старый файл), а встроенная раздача adapter-node держит таблицу файлов
(размер, etag) со сборки. `server/index.js` рисует карточки через `server.respond` напрямую,
остальное отдаёт стандартному `handler`.

### Студия — статика с выдачей в браузере

`/studios/{slug}` устроена как карточка: `+page.server.ts`, `prerender = 'auto'`, бэкенд шлёт
адрес в ISR, когда меняются фильмы студии. При сборке студии не пререндерятся (`entries` нет):
первое открытие студии бэкенд дополняет из TMDB (1–2 с), на тысячи студий сборка бы встала. Файл
появляется при первом запросе; пока идёт переход, ссылка на студию (в карточке, «Входит в»)
показывает индикатор.

В статике — студия и первая порция фильмов в порядке по умолчанию (`recommended`). Load не читает
адрес: nginx отдаёт файл без учёта query, а с `url.searchParams` сервер нарисовал бы одно, а
браузер получил бы другое. Порядок живёт в `?sort=` (ссылкой можно поделиться), его читает
страница после монтирования и грузит выдачу сама (`studioFilms`); пока грузится — прежняя
выдача, приглушённая. «Показать ещё» и оценки Nexus — тоже в браузере. Ошибка API при рисовании
— ошибка страницы (`orError` и для списка): сбой не должен застыть в статике.

### Архив в выдаче

Галочка «Архив» (`/films`, `/search`) выключена по умолчанию, включённая — `archive=1`. Фильмы
архива идут в той же выдаче за фильмами сайта, счётчик — сумма сайта и архива. Архив — Tantivy на
бэкенде, только поиск по названию: без названия он ничего не добавляет (страница пишет «архив
ищется только по названию»), фильтры по тегу, году, студии к нему не применяются.

Архив грузит страница в браузере (`#lib/catalog/archive.svelte.ts`), а не load: load не читает
`archive`, поэтому переключатель не перезапрашивает выдачу сайта; пока архив отвечает — «ищем в
архиве…». Клик по фильму архива — `/archive/{slug}`:
код страницы грузится, как только карточка на экране, код карточки фильма — параллельно с
возвратом (`preloadCode`), так что после возврата ждать остаётся только `__data.json`.

### Загрузка каталога

Данные каталога грузятся в `+page.ts` через `publicApi` — на сервере при первом заходе, в
браузере при переходах. Независимые запросы идут параллельно (`Promise.all`). Хелперы
(`#lib/catalog/load.ts`):

- `orError()` — для карточек: 404 → страница 404, остальное → `+error.svelte`;
- `settle()` — для списков и необязательных частей: ошибка → `{ error }`, страница показывает
  `LoadError` с «Повторить» (`invalidateAll`), фильтры остаются на месте.

**Списки — только из Meilisearch** (`GET /search`, `#lib/catalog/search.ts`): разделы, `/search`,
главная, теги, фильмы студии. `GET /entities` (PostgreSQL) для списков не используем: сортировка
всего каталога там бывает по 7–8 с, у Meilisearch — десятки миллисекунд. `total` у поиска точный,
порядки — те же, что были у списка (`LIST_SORTS`, в том числе по оценкам Nexus: в индекс они
попадают с задержкой до минуты), фильтр по людям и `studio_slug` работают. Из PostgreSQL — только одна сущность по slug (карточка — статика, рецензии, темы), тег и
студия (`GET /tags/{slug}`, `GET /studios/{slug}`), и обход всего каталога при сборке и в ISR.

`hooks.server.ts` разрешает читать на сервере заголовки ответов API `content-length`,
`transfer-encoding`, `retry-after` (`filterSerializedResponseHeaders`): openapi-fetch смотрит
`Content-Length`, без этого любой SSR-запрос падает с `load_response_header_not_serialized`.

**Карточка** (`routes/[kind=kind]/[slug]/+page.svelte`, `components/card/`, `#lib/catalog/card.ts`).
Сверху вниз:

1. `StickyHeader` — только на телефоне: мини-постер, название, колокольчик. Выезжает под шапкой
   сайта, когда первый экран ушёл вверх (IntersectionObserver).
2. `Hero`: есть трейлер — шапка Okko (`CardHero`, ниже), постера нет; нет трейлера — постер слева,
   тот же текст справа. В шапке русское название, под ним жанры (теги `kind = genre`), кнопки, под
   ними отметки «Посмотреть позже» / «Просмотрено» (`MarkButtons`, `Marks`: `GET/PUT/DELETE
…/mark` с токеном). Кнопки (стиль —
   `components/card/buttons.ts`; «Трейлера» пока нет — он идёт фоном, `TrailerButton` не
   используется): средняя (`AverageRating`, ссылка на `/reviews`), «Оценить» (`RateButton`: панель 1–10 и реакции
   🔥😢🤔😴, до премьеры — неактивна), «В коллекцию», колокольчик «Следить» с тултипом.
3. Теги без жанров (`TagChips`), под ними `About` — «О фильме», две плашки. Первая — одна таблица с подписями: оригинальное название
   (`originalTitle`), описание (`Clamp`: «Читать далее…», только если правда не влезло), таблица
   как у Кинопоиска (`aboutRows`): год, страна, съёмочная группа по ролям, премьера, metadata;
   вторая, отдельно — главная роль (`peopleCard`, `leadRole`: режиссёр, у книг автор) и «В главных
   ролях» с фото (9 + «Ещё N»). Подробности — только здесь.
4. `Related` — приквелы, сиквелы, ремейки (`EntityDetail.related`, в статике), только непустые
   группы; связей нет — раздела нет. `Recommendations` — `GET …/similar` в браузере, пока грузится
   — скелетон, пустая подборка — раздела нет.
5. `Production` — справа от таблицы «О фильме» (`About` aside, `productionOf`): студии (у фильмов и
   сериалов — `EntityDetail.studios`, ссылки на `/studios/{slug}` с логотипом; названия, для
   которых бэкенд ещё не завёл студию, он не отдаёт; у игр — разработчик и издатель, у книг —
   издательство из metadata), награды (победы и номинации), факты — из metadata. Нет ничего — нет
   и колонки.
6. Ленивая зона (`ClientSection`): `ActivityFeed` — одна плашка: вкладки «Рецензии / Обсуждения»
   (по умолчанию рецензии), строка «Что думаете о
   фильме?» с пилюлями «Рецензия» / «Обсуждение» (на её месте — `ReviewComposer`), до 4 записей по
   дате (`ReviewCard`/`ThreadItem` с `flat`) в своей вкладке, ссылки на полные списки — только в
   своей вкладке и если записей больше; «В коллекциях».

Общие состояния на страницу: `Watch` (`#lib/social/watch.svelte.ts`) — «Следить» в шапке и
липкой шапке; `MyReviewState` (`#lib/social/my-review.svelte.ts`) — «Оценить» в шапке и форма
рецензии в ленте пишут одну рецензию; `MyVotes` (`#lib/social/review-votes.svelte.ts`, контекст)
— свои голоса за рецензии одним запросом `votes/mine` на карточку. Вышло ли (`isReleased`) — по
часам зрителя, не сборки; до премьеры бэкенд ещё и отвечает 409 `not_released`.

**Личное — отдельно от публичного.** Рецензии, сводка, комментарии, похожие, оценки пачкой —
без токена (`browserApi` / `publicApi`): одинаковы для всех и кэшируются. «Мой голос», «моя
реакция», «моя отметка» — своими запросами с токеном, только у вошедшего, перечитываются при
входе и выходе. Нажатие меняет экран сразу (оптимистично), ошибка — откат и `errorMessage()`.
Реакции: числа — `RatingSummary.reactions` (тот же запрос, что сводка), своя — `…/reaction`.
Старые ключи `localStorage` (голоса, отметки, реакции) удаляются при загрузке
(`#lib/utils/legacy-storage.ts`).

**Шапка Okko** (`CardHero`, `TrailerButton`, `#lib/catalog/trailer.ts`,
`trailer-player.svelte.ts`). Шапка — фон
на всю ширину: трейлер сам запускается без звука, без элементов управления, по кругу (iframe
`pointer-events-none`, чуть увеличен, чтобы срезать подписи плеера); звук, пауза, полный экран —
нашими кнопками через `postMessage`-команды плееру. Свой интерфейс плеера спрятан: у YouTube `controls=0`, Rutube
получает `player:enterNakedMode` и `player:hideControls` (команда `bare`) при загрузке, старте и
после каждого «играть». На паузе и вне экрана iframe гаснет до размытой обложки — значок паузы и
«Другие видео» плеера посреди кадра не видны. Вне экрана — пауза; `prefers-reduced-motion` —
не запускается. Поверх (на телефоне — под видео): тип, название, факты (`keyFacts`: год, теги,
длительность / сезоны, возрастной рейтинг), описание, «Режиссёр: …» (`leadCredits`), кнопки.

Источники — `metadata.trailers` у фильмов, сериалов и игр (`youtube`, `rutube` по приоритету:
YouTube заблокирован в части стран СНГ и в Китае). id ещё раз проверяется шаблоном провайдера,
адрес плеера строит фронтенд (`youtube-nocookie.com/embed/{id}`, `rutube.ru/play/embed/{id}`):
бэкенд не отдаёт готовых ссылок, чтобы в iframe не попал чужой домен. Выбор источника — в живом
плеере (`TrailerPlayer`, общий для фона и модалки): старт с запомненного провайдера
(`localStorage` `nexus.trailer.provider`), события плеера по `postMessage` с проверкой `origin`
(YouTube — после рукопожатия `listening`, оно повторяется каждые 250 мс, пока плеер не ответит:
на медленной сети первое теряется; Rutube — `player:changeState`). Rutube не понимает `mute=1` и со
звуком сам не стартует, поэтому после `player:ready` фон шлёт ему «без звука» и «играть». Нет
воспроизведения за 8 с или ошибка — следующий источник; на фоне — даже если плеер загрузился
(нажать ▶ на фоне нельзя), в модалке — только если плеер молчит или завис на загрузке.
Сработавший провайдер запоминается. iframe фона проявляется, когда заиграл именно текущий
источник (`load` у Rutube приходит позже начала воспроизведения).

«Трейлер» — модалка `<dialog>` с полноценным плеером со звуком: iframe создаётся при открытии и
удаляется при закрытии, фон на это время на паузе. Над плеером переключатель источников, при
автопереходе — «YouTube недоступен, показываем Rutube», не сработал ни один — «Трейлер недоступен
в вашем регионе». В e2e видеосервисы и CDN подменены (`page.route`), адреса плееров строятся из
ответа API, таймаут проматывается `page.clock`.

**Живое на статической карточке** (`#lib/social/card-live.svelte.ts`). В HTML и `__data.json`
только каталог; оценки, рецензии, обсуждения и коллекции грузятся в браузере из API:

- `liveQuery(deps, load)` — запрос в `$effect`: повтор при смене `deps`, старые данные видны до
  ответа, устаревший ответ отбрасывается, `retry()` для `LoadError` (`onretry`);
- `CardLive` — один на страницу: `refresh()` перечитывает все живые блоки. Его зовут реалтайм
  (`entity:<slug>`, пачка за 0,8 с), «Ваша оценка», «В коллекцию», удаление модератором
  (`ReviewCard` `onremoved`). `invalidateAll` здесь не помог бы — перечитал бы статику;
- сводка оценок грузится сразу (бейдж в шапке и раздел рецензий), остальное — блоками
  `ActivityFeed`, `CardCollections` внутри `ClientSection`: блок монтируется, когда
  раздел подходит к экрану (IntersectionObserver, за 200px), до этого — заглушка высотой примерно с
  содержимое (`placeholder`). Нижние разделы не запрашиваются, пока до них не долистали; в e2e к
  ним надо прокрутить (`scrollIntoViewIfNeeded`).

**Оценки и рецензии** (`#lib/social/reviews.ts`, `components/social/`). На карточке: средняя в
шапке (7+ зелёная, 5+ жёлтая, ниже красная) — ссылка на `/reviews`, где сводка (`RatingSummary`),
«Ваша оценка» (`MyReview`) и все рецензии с сортировкой (`?sort=new|rating_desc|rating_asc`).
«Оценить» — в шапке, рецензии — в ленте вместе с темами. `ReviewCard`: длинный текст свёрнут до 6
строк («Читать полностью»), рецензия со спойлером (`is_spoiler` — галочка «Есть спойлеры» в
форме) размыта `blur-md` с кнопкой «Спойлер. Нажмите, чтобы открыть»; пока размыта —
`inert` и `aria-hidden`. Сводка и рецензии — живые блоки (см. выше): не загрузились — `LoadError` с
«Повторить», карточка остаётся. «Ваша оценка» — только в браузере: своя
рецензия `GET …/review` (404 — нет), клик по 1–10 сразу сохраняет (`PUT`, текст не теряется),
повторный клик снимает оценку, «Написать рецензию» — форма до 10 000 символов, «Удалить» — с
подтверждением. После изменения — `live.refresh()`: сводка и список перечитываются, трейлер в
шапке не перезапускается. В списке только рецензии с текстом (оценки без текста — в сводке).
Текст рецензии — обычный текст (`whitespace-pre-line`), без `{@html}`. Под текстом — 👍/👎 с
числами (`ReviewActions`) и «Комментарии N» (`ReviewComments`: публичный список, старые сверху,
«Показать ещё», своё «Удалить», админу — модерация; события `review.commented` /
`review.comment_deleted` перечитывают ленту, открытый список — по смене `comments_count`).

**Профили и подписки** (`routes/u/[username]/`). Шапка — в `+layout.ts` / `+layout.svelte` для
всех вкладок: `GET /users/{username}` на сервере как для гостя (`relation = null`), 404 — нет или
заблокирован. `FollowButton` в браузере перечитывает профиль с токеном, чтобы узнать
`relation` и `liked` (`ProfileViewer`, `#lib/social/profile-viewer.svelte.ts` — один запрос на обе
кнопки): «Подписаться» / «Вы подписаны» (наведение — «Отписаться») / «Читает вас»; на своём
профиле — «Редактировать профиль», гостю — вход с возвратом. Подписка меняет счётчик
подписчиков сразу, без перезагрузки шапки. «Коллекции» — пока заглушка до блока коллекций; темы
ведут на `/forum/{id}` (блок форума).

В шапке также «о себе» (`bio`), «на сайте с …» (`registered_at`), «Нравится» (`LikeButton`:
`PUT`/`DELETE …/users/{username}/like`, лайк один, дизлайка нет; себе — нельзя, бэкенд отвечает
400 `like_self`) и рейтинг («карма», `ReputationBadge`) с подсказкой «из чего сложился балл»
(`reputation.parts`). Счётчик лайков и `liked` приходят в самой шапке — отдельного запроса под
кнопку нет. **Балл после лайка не анимируется:** пересчёт идёт раз в сутки целиком, поэтому свежий
лайк виден в `likes_count` сразу, а в `reputation.score` — только после ближайшего прохода;
`computed_at: null` — пересчёта ещё не было и балл стартовый (30 за регистрацию).

**Аналитика профиля — одна вкладка «Статистика»** (`/u/{username}/stats`; `#lib/social/profile.ts`,
`profile-data.svelte.ts`, `profile-list.svelte.ts`). Сверху сводка (средняя, распределение 1–10,
отметки, реакции, комментарии, разрез по типам), под ней три списка: **что оценено, где стоят
отметки и где оставлены комментарии** — чтобы из профиля было видно, куда ты это поставил. Своих
вкладок у списков нет: это один разговор про пользователя, а не четыре.

Закрыта по умолчанию: четыре эндпоинта отвечают чужому и гостю **403 с `code: "stats_private"` —
это штатный ответ, а не сбой** (`isStatsPrivate` в `errors.ts`), тоста об ошибке быть не должно.
Рисовать вкладку или нет, решает `canSeeStats` по `stats_public` из шапки; владелец и админ видят
её всегда. Данные грузятся в браузере (`profileQuery`), а не в `+page.ts`: на сервере токена нет,
и владелец получил бы 403 на собственной странице — шапка при этом остаётся серверной. Общая
обвязка (скелетон, «закрыто», ошибка с «Повторить») — `StatsBlock`; списки монтируются только
после сводки, иначе при закрытой статистике они собрали бы те же три 403 без пользы.

Четвёртый список — **«Что нравится»** (`ProfileLikes`, `GET /users/{username}/likes/given`):
лайкнутые подборки и люди с фильтром по виду. Счётчики `likes_given` — в сводке (произведений
там нет, см. «Лайки»).

Списки (`profileList`, оформление — `StatsSection`) дочитываются по «Показать ещё», а порядок
оценок и вид отметок живут в состоянии раздела, а не в адресе: на странице три списка сразу,
и один `?sort=` на всех не поделить. В ленте комментариев цель — дискриминированное объединение
по `target.kind` (`entity`, `person`, `studio`, `review`, `collection`); ссылку и подпись даёт
`commentPlace`, незнакомый вид — подпись без ссылки.

Подписчики и подписки вкладками не дублируются — на них ведут счётчики в шапке
(`/u/{username}/followers`, `/following`).

**Фото профиля** (`#lib/auth/avatar.ts`, `AvatarUpload`). `POST /auth/me/avatar` — multipart
с одним файловым полем (FormData уходит через openapi-fetch как есть, `Content-Type` с границей
ставит браузер), `DELETE` убирает и файл, и аватар от провайдера. До 2 МБ, ошибки —
`file_too_large` / `not_an_image`, 429 с `Retry-After` (10 загрузок за 10 минут). Сервер
пережимает в WebP (длинная сторона 512 px) и квадрат не вырезает — кадрируем через
`object-fit: cover` в `Avatar`. **`avatar_url` бывает и относительным
(`/api/v1/auth/avatars/{id}` у загруженного файла), и абсолютным (`https://…` у Google и GitHub)
— с базовым адресом не склеиваем ни тот, ни другой (`avatarSrc`).** Свой `avatar_url` в
`PATCH /auth/me` удалил бы загруженный файл, поэтому настройки его не шлют. Там же — «о себе»
(`bio`, до 1000, пустая строка очищает) и переключатель «показывать мою статистику всем»
(`stats_public`).

**Комментарии к произведениям, людям и студиям** (`#lib/social/comments.ts`, `TargetComments`).
`GET/POST /social/comments?target=entity:dune-2021` (`person:`, `studio:`),
`DELETE /social/comments/{id}`. Лента плоская, старые сверху, ветка ровно одного уровня: ответ на
ответ бэкенд привязывает к корню, поэтому группируем по `parent_id` без рекурсии
(`threadComments`); ответ, корень которого не попал на страницу, показывается корневым. Список
публичный, отправка и удаление — с токеном; админу — модерация (`/admin/comments/{id}`). body
1–2000, лимит 5 в минуту (429 с `Retry-After: 60` — текст «Попробуйте через 60 с» даёт
`translate`). На карточке — ленивый раздел «Комментарии» (`ClientSection`), на страницах человека
и студии — раздел внизу. Комментарии к рецензиям и обсуждения подборок остались на своих старых
адресах.

**Лайки** (`#lib/social/likes.ts`). Сигнал «мне нравится» — чтобы человек видел в своём профиле,
что ему зашло. Подборке ставят **лайк и дизлайк** (`CollectionLikes` в `CollectionEnd`, обычный
вид и особый), человеку — **только лайк** (`PersonLikeButton` на `/people/{slug}`), профилю —
тоже только лайк (`LikeButton`). У произведений лайков нет и не будет: там оценки 1–10, отметки
и реакции; бэкенд принимает `target=entity`, но всегда отдаёт пустую страницу, поэтому такого
фильтра в интерфейсе нет.

Голос за подборку — один на зрителя: другой переставляет, тот же снимает. Это ровно механика
голосов за рецензии, поэтому счёт ведёт тот же `applyVote`. Счётчики приходят в самой подборке
(`likes_count`, `dislikes_count`) и в карточке человека (`PersonDetail.likes_count`) — второго
запроса ради чисел нет. **Свой голос — другое дело:** сервер рендерит страницу как для гостя, и
`mine` / `liked` там всегда пустые, поэтому вошедший один раз перечитывает их с токеном
(подборка — `GET …/collections/{id}/likes`, человек — свою карточку каталога; отдельного «мой
лайк» у человека в API нет, а листать список лайкнувших ради одной проверки не стоит).
Нажатие меняет числа сразу, ошибка — откат.

Поле у подборки называется `mine` (1, −1 или `null`), а не `liked`: голос трёхзначный. Там, где
дизлайка нет (профиль, человек), осталось булево `liked`.

В `PersonRef` лайков нет намеренно (он идёт в каждом списке и в каждой ленте) — в карточках
списков счётчик не показываем; понадобится — у бэкенда есть заготовка батч-эндпоинта.

Реакции 🔥 😢 🤔 😴 у подборок на бэкенде пока остались, но фронтенд на них больше не ходит:
`CollectionReactions` удалён вместе с переключением на лайки. Реакции на **произведениях**
(`Reactions` на карточке) никуда не делись — это разные вещи.

**Форум** (`#lib/social/forum.ts`, `routes/forum/`, `(protected)/forum/`). Тема привязана к 1–10
произведениям, первое — главное. Сообщения приходят плоским списком по времени (`parent_id`):
ветка показывается цитатой «↳ в ответ @user: «начало текста»» со ссылкой к исходному, если оно на
этой странице (`quoteFor`); исходное удалено — «в ответ на удалённое сообщение». Удалённые с
ответами — заглушка «Сообщение удалено». Текст — простой, адреса http(s) становятся ссылками
(`RichText` + `linkify`, без `{@html}`, `rel="nofollow noopener ugc"`). Время — «5 минут назад»
в браузере, на сервере — дата (`TimeAgo`, без расхождений при гидрации). После ответа —
переход на последнюю страницу к новому сообщению (`goto(…#post-id, { refreshAll: true })`).
Темы создают `author` и `admin` (`NewThreadButton`; остальным — подсказка); править тему и
сообщение может только автор. Произведения в форме выбираются поиском (`EntityPicker`:
только `/search`). На карточке — «Обсуждения» (5 тем, `GET
/entities/{slug}/threads`) и «Начать обсуждение» (`/forum/new?entity=slug`). Модерация (закрыть,
удалить чужое) — в админке.

**Коллекции** (`#lib/social/collections.ts`, `routes/collections/`). Публичная коллекция
рендерится на сервере; на чужую или свою личную сервер получает 404 и отдаёт заготовку
(`noindex`), а в браузере `+page.ts` перечитывает коллекцию с токеном (`ensureSession` + `api`):
владелец видит свою личную, остальным — 404. Вкладка «Коллекции» в профиле: сервер — публичные,
владельцу в браузере — вместе с личными. Владелец правит название, описание и видимость,
удаляет коллекцию, а в режиме «Изменить содержимое» (`CollectionEditor`) добавляет произведения
поиском, пишет заметки, убирает и переставляет: перетаскиванием (HTML5 drag and drop) и
стрелками (телефон, клавиатура); порядок сразу сохраняется целиком (`PUT …/items`). На карточке —
«＋ В коллекцию» (`AddToCollection`: свои коллекции с отметками и быстрое создание; отметки —
одним запросом `?contains={slug}`) и «В коллекциях» (публичные, `GET
/entities/{slug}/collections`).

**Интересы и лента.** «🔔 Следить» на карточке (`WatchButton`, `GET/PUT/DELETE
/entities/{slug}/interest`) — темы и рецензии сущности идут в ленту и приходят вживую. `/feed`
(группа `(protected)`, без SSR): записи с причиной («вы подписаны», «вы следите за …»,
«популярное», `FeedItem`), фильтр `?type=`, пагинация курсором — «Показать ещё»; справа — список
интересов с отпиской.

## Админка

`routes/(protected)/admin/` — только роль `admin` (остальным «Нет доступа»; бэкенд проверяет каждый
запрос сам), ссылка «Админка» в меню пользователя.

| Раздел       | Что можно                                                                                                                                                                                                                                                                                                                        |
| ------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Обзор        | ссылки на разделы                                                                                                                                                                                                                                                                                                                |
| Произведения | список с фильтрами; создание и правка (`EntityForm`): тип, slug из оригинального названия и года (`slugify` с транслитом), поля, обложка с превью, metadata по типу (`entity-form.ts`), трейлеры по приоритету (ссылка — провайдер определяется сам), теги; участники (`CreditsEditor`); связанные (`RelationsEditor`); удаление |
| Люди         | список с поиском, форма с превью фото, удаление                                                                                                                                                                                                                                                                                  |
| Теги         | создание, правка на месте (и вид: жанр или тег), удаление                                                                                                                                                                                                                                                                        |
| Пользователи | поиск по имени и email, роль и блокировка (себя — нельзя)                                                                                                                                                                                                                                                                        |
| Индексация   | по разделам (`ReindexPanel`): поиск — новый индекс без простоя, статические страницы — пересборка в фоне; лог шагов, подтверждение, «без проверки» при отказе 80%. Сейчас — произведения; люди — «скоро», пока у бэкенда нет их индекса                                                                                          |

**Публикация и перестройка — с логом.** Сохранение произведения идёт через
`PATCH …/admin/entities/{id}/stream`, перестройка поиска — `POST …/admin/search/reindex/stream`.
Перестройка — в разделе «Индексация» (`/admin/index`). Обе отдают поток `JobEvent` (`plan` → `step`/`progress` → `done`), его показывает один компонент
`JobLog`: шаги из плана, статусы, время, прогресс длинных шагов, итог. Поток читается из `fetch`
(`parseAs: 'stream'` в openapi-fetch, токен и refresh — как у `api`): `EventSource` не умеет PATCH и
`Authorization`. Разбор SSE и состояние лога — `#lib/admin/job.ts` (без Svelte, unit-тесты).
Ошибки ввода (400/404/409) приходят до потока обычным JSON. Обрыв до `done` — сообщение «связь
прервалась»: запись бэкенд доводит до конца сам. Теги — отдельный `PUT` до потока, чтобы шаг ISR
уже видел их. Новый индекс меньше 80% текущего — шаг `check` падает, появляется «Перестроить без
проверки» (`?force=true`).

**Модерация — на месте** (`ModerateButton`, видна только админу): удалить чужую рецензию, сообщение,
коллекцию, тему; закрыть и открыть тему. В закрытой теме админ может отвечать. Очереди жалоб нет —
бэкенд их не хранит.

E2E админки (`e2e/admin.spec.ts`) идут последовательно с одним входом под `admin` на файл;
созданное удаляется, сидовые данные возвращаются как были.

## Реалтайм

`#lib/realtime/client.ts` — WebSocket-клиент без Svelte (сокет, таймеры и токен — снаружи, unit-
тесты на фейковом сокете); `realtime.svelte.ts` — одно соединение на вкладку и
`useRealtime(channels, onEvent, onResync)` для компонентов. Протокол —
`../nexus_project/documents/modules/realtime.md`; `/ws` проксируется так же, как `/api`.

- Соединение открывается при первой подписке или входе; вход — по сессии (`syncRealtimeAuth` в
  корневом layout): `auth` с access-токеном, выход — новое гостевое соединение.
- Токен живёт 15 минут: за 25 с до `expires_at` клиент снова шлёт `auth` (`accessToken()` к этому
  моменту обновляет токен сам). Не успел (вкладка спала) — на `auth_expired` входит заново.
- Подписки со счётчиком: несколько компонентов на одном канале — одна подписка на сервере.
  `user:me` и каналы интересов сервер подписывает сам — клиент их не шлёт.
- Обрыв — переподключение через 1, 2, 4, … 30 с, затем `auth` и `subscribe` заново; подписчикам —
  `onResync` (и на `lagged`): пропущенное не повторяется, экран перечитывает данные.
- В событиях только id — данные перечитываются по API.

| Где                | Каналы          | Что делает                                                                                                                                |
| ------------------ | --------------- | ----------------------------------------------------------------------------------------------------------------------------------------- |
| Тема `/forum/{id}` | `thread:<id>`   | чужие новые сообщения — плашка «N новых — показать»; правка, удаление, закрытие — тихо перечитать; тема удалена — сообщение               |
| Карточка           | `entity:<slug>` | чужие рецензии и темы — перечитать сводку, рецензии, обсуждения (пачкой, через 0,8 с)                                                     |
| Везде (вошедший)   | `user:me`       | `reply.created` — уведомление «Вам ответили» (`ReplyToasts`) со ссылкой `/forum/{id}?post=…`; `interest.*` — «Следить» на других вкладках |
| Лента              | все события     | новое по интересам — плашка «Есть новое — обновить»                                                                                       |

`/forum/{id}?post=<id>` — если сообщения нет на первой странице, открывается последняя: «на какой
странице сообщение» API не говорит, а ответ из уведомления свежий.

SEO: `Seo.svelte` — `<title>`, `meta description` (обрезанное по слову описание), `og:*`.

## API-клиент

- **Типы** генерируются из `../nexus_project/documents/api/{openapi,catalog,social}.json` в
  `src/lib/api/generated/{auth,catalog,social}.ts` (`pnpm api:types`) и коммитятся. CI сверяет их
  с контрактом (`pnpm api:check`). Скрипт сначала проверяет контракт: ссылка на отсутствующую
  схему или повторяющийся `operationId` — падение с перечнем ошибок (чинится в бэкенде).
- **Клиенты** — по одному на контракт: `api.auth`, `api.catalog`, `api.social`. Пути полные:
  `api.social.GET('/api/v1/social/users/{username}', { params: { path: { username } } })`.
- Какой клиент брать:
  - `api` (`#lib/auth/session.svelte.ts`) — в браузере от имени пользователя: Bearer, обновление
    токена, повтор на 401;
  - `guestApi` — вход, регистрация, ссылки из писем: без токена;
  - `publicApi(fetch, url)` (`#lib/api/client.ts`) — в `+page.ts`, публичные данные. На сервере
    запрос идёт на `url.origin/api/...`, а `handleFetch` отправляет его на `BACKEND_URL`.
- **Ошибки.** Бэкенд отвечает `{"error", "code", "retry_after"?}`: `error` — английский текст для
  логов, `code` — машинный код (таблица — `nexus_project/documents/for-other-modules.md`).
  `unwrap()` превращает ответ в данные или `ApiError { status, code, serverMessage, message }`, где
  `message` — текст для пользователя: по `code` (словарь `BY_CODE` в `errors.ts`); у `validation`
  код общий — текст уточняется по `serverMessage`, иначе — по статусу. Сбой сети — `ApiError(0)`.
  Для 429 срок берётся из `retry_after` в теле или заголовка `Retry-After`: «Попробуйте через 80 с».
  403 с `code: "stats_private"` — не ошибка, а «владелец закрыл статистику»: `isStatsPrivate`
  отделяет его от настоящих сбоев, и вместо сообщения об ошибке страница объясняет, что закрыто.
  В компоненте: `catch (e) { error = errorMessage(e) }`.

## Прокси и окружение

| Где                        | /api и /ws                                                               |
| -------------------------- | ------------------------------------------------------------------------ |
| `pnpm dev`, `pnpm preview` | прокси Vite → `BACKEND_URL` (по умолчанию `http://localhost`)            |
| SSR (сервер SvelteKit)     | `handleFetch` → `BACKEND_URL`                                            |
| прод                       | тот же домен, nginx (позже: фронтенд — отдельный сервис за тем же nginx) |

Docker для фронтенда пока не делаем — появится вместе с деплоем (образ `adapter-node`). Прод —
`node server/index.js` за nginx (`deploy/nginx.conf`), см. «Карточка — статика и ISR».
