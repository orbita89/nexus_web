# Переход на прод: статика страниц

Что сделать, чтобы на проде страницы книг (а потом и остальные) отдавались готовыми `.br`-файлами
с диска или из CDN. Как устроены страницы — `docs/pages.md`.

**Схема.** Все страницы генерируются **на локальной машине** одной сборкой и одной командой,
готовые файлы целиком переносятся на прод. Прод сам всё заново не генерирует: он только отдаёт
файлы и дорисовывает одиночные страницы — новые книги и правки из админки.

## 0. Три правила, без которых не работает

1. **Сборка одна — и для генерации, и для прода.** В каждом HTML есть ссылки на JS и CSS этой
   сборки (`/_app/immutable/<хэш>.js`). Если сгенерировать страницы одной сборкой, а на прод
   выложить другую, у страниц не будет скриптов: они откроются, но не оживут (кнопки, оценки,
   переходы). Поэтому на прод уезжает **весь** `build/`: сервер, ассеты и страницы вместе.
2. **Адреса в страницах — продовые.** В HTML зашиты абсолютные адреса:
   - `canonical`, `og:url`, JSON-LD — из `ORIGIN` при сборке;
   - обложки (`cover_url`, `og:image`, preload) — из ответа API, их строит бэкенд из своего
     `PUBLIC_URL`.

   Собранные с `http://localhost`, страницы будут ссылаться на localhost: поисковик получит чужой
   canonical, а у читателя не загрузятся обложки. Поэтому `ORIGIN` фронтенда и `PUBLIC_URL`
   локального бэкенда при генерации — **адрес прода**.
3. **Данные — продовые.** Страница рисуется из API локального бэкенда. Его база должна совпадать
   с продовой (тот же дамп): те же slug, описания, обложки. Иначе на проде будут страницы книг,
   которых там нет, а книги прода — без страниц (дорисуются при первом заходе).

## 1. Один раз: подготовка прода

### Сервер фронтенда

- Node 22+, каталог релизов: `/srv/nexus-web/releases/<id>/`, симлинки `current` и `previous`
  (`deploy/nginx.conf` берёт из `previous` старые чанки).
- Сервис (systemd или контейнер): `node server/index.js` в каталоге `current`, окружение:

  | Переменная | Значение |
  |---|---|
  | `HOST`, `PORT` | `127.0.0.1`, `3000` (или адрес, который видит бэкенд — см. ниже) |
  | `ORIGIN` | `https://<домен>` |
  | `ISR_SECRET` | случайная строка (`openssl rand -base64 48`), **та же**, что у бэкенда |
  | `BACKEND_URL` | адрес API для полной пересборки (`http://127.0.0.1:8080` или `https://<домен>`) |
  | `ISR_CONCURRENCY` | `8` (сколько страниц рисовать одновременно) |

### nginx

- `deploy/nginx.conf` — пример server-блока. Обязательно перенести:
  - `map $http_accept_encoding $nexus_br_suffix` — на уровне `http` (выше `server`);
  - два location книг (`/books/…/__data.json` и `/books/…`) — **раньше** общего location карточек;
  - `location /_isr/ { return 404; }` — перерисовка только изнутри.
- Модуль `ngx_brotli` нужен для остальных статических файлов (`brotli_static`); для книг — нет:
  nginx отдаёт готовый `.br` как файл.
- **HTTPS обязателен**: браузеры просят brotli только по HTTPS.
- Без `open_file_cache`: перерисовка заменяет файлы через `rename`.

### Бэкенд (nexus_project, `infra/docker-compose.prod.yml`)

- `ISR_URL` — адрес сервера фронтенда, **достижимый из контейнера бэкенда**. `127.0.0.1` хоста
  из контейнера не виден: либо фронтенд слушает адрес docker-моста и `ISR_URL=http://<он>:3000`
  (+ `extra_hosts: host.docker.internal:host-gateway` → `http://host.docker.internal:3000`), либо
  фронтенд в той же docker-сети (`http://web:3000`).
- `ISR_SECRET` — тот же, что у фронтенда.
- `PUBLIC_URL=https://<домен>` — из него строятся адреса обложек.

Проверка связи (с машины бэкенда): `curl -s -H "Authorization: Bearer $ISR_SECRET" $ISR_URL/_isr/status`
→ `{"run":null}` или ход последней пересборки.

### Файлы книг (читалка)

Книгу отдаёт бэкенд: `GET /api/v1/catalog/books/{slug}/epub` достаёт EPUB из тома `.arx` и кэширует
извлечённый файл (`modules/catalog/src/books/reader.rs` в nexus_project). CDN закрытые книги не
кэширует (`Cache-Control: private`).

- **Тома `.arx`** — на HDD, в контейнер только на чтение: `BOOKS_ARCHIVES_HOST=/mnt/books/archives`
  (`infra/docker-compose.prod.yml`). Нет тома для книги — 503 «архив книги недоступен».
- **Кэш извлечённых EPUB** — том `epubcache` (`/var/cache/nexus-epub`), лучше на SSD: популярные
  книги не читают HDD повторно. **Размер жёстко ограничен** `BOOKS_EPUB_CACHE_MB` (2048 по
  умолчанию). После каждого извлечения и при старте бэкенд удаляет давно не открытые книги сверх
  предела, брошенные `.tmp-*` (падение посреди извлечения) и пустые каталоги. Кэш можно в любой
  момент удалить целиком (`docker volume rm …_epubcache`) — книги извлекутся заново.
- **Не оставлять кэш по умолчанию**: без `BOOKS_EPUB_CACHE_DIR` он пишется в `/tmp` контейнера и
  раздувает сам контейнер.
- **Память**: файл отдаётся потоком с диска, не целиком в RAM.
- Предел подбирать так, чтобы `BOOKS_EPUB_CACHE_MB` + остальное на диске оставляло запас ≥ 10%.
  Проверка: `docker compose … exec app du -sh /var/cache/nexus-epub`.

### CDN

Нужен CDN, который **тянет файлы с nginx прода** (origin pull), а не хранилище, куда файлы
заливаются руками. Причины:

- правка в админке перерисовывает страницу на диске прода — CDN заберёт новую версию сам, когда
  истечёт кэш (5 минут, `Cache-Control: public, max-age=300`);
- клиенту без brotli `.br` распаковывает Node — в «голом» хранилище этого никто не сделает.

Настройки CDN:

- **Кэш учитывает сжатие**: CDN должен соблюдать `Vary: Accept-Encoding` (мы его отдаём) или
  делить кэш на «с br / без br». Иначе закэшированный `.br` уйдёт клиенту без brotli — тот увидит
  мусор. В панели CDN: «кэшировать сжатые варианты», «normalize Accept-Encoding» и т.п.
- **Не пережимать**: отключить сжатие на стороне CDN для ответов, у которых уже есть
  `Content-Encoding` (обычно так по умолчанию).
- `/_app/immutable/*` — кэшировать навсегда (заголовок уже `immutable`).
- `/api/*`, `/ws`, `/_isr/*` — **не кэшировать**, проксировать как есть.
- Сброс кэша после выкладки нового релиза — весь сайт (у страниц новые ссылки на чанки).

## 2. Каждый релиз: генерация на локальной машине

### 2.1. Подготовить данные

1. Свежий дамп базы прода → локальный PostgreSQL (как обычно в nexus_project).
2. Локальный бэкенд с продовым `PUBLIC_URL`:
   ```
   cd nexus_project
   PUBLIC_URL=https://<домен> docker compose -f infra/docker-compose.yml up -d
   ```
3. Индексы актуальны: в `/admin/books` книжный индекс без предупреждения «индекс отстал»
   (иначе — «Перестроить всё»).

### 2.2. Собрать и сгенерировать

```
cd nexus_web
ORIGIN=https://<домен> PRERENDER_ENTITIES=1 pnpm build     # сборка + фильмы, сериалы, игры, картины
ORIGIN=https://<домен> ISR_SECRET=local HOST=127.0.0.1 BACKEND_URL=http://localhost pnpm start &
ISR_SECRET=local pnpm revalidate --all --kind book --wait  # все книги, с прогрессом
```

- `pnpm build` с `PRERENDER_ENTITIES=1` пререндерит все карточки, кроме книг (их рисует третья
  команда). Падает, если бэкенд недоступен.
- `--wait` печатает ход раз в 5 секунд и выходит с кодом 1, если были ошибки (список — в конце).
  Ошибочные страницы — `pnpm revalidate /books/<slug> …` или ещё раз `--all --kind book`
  (неизменившиеся страницы не перезаписываются, повтор дешёвый).
- Время: на 315 тыс. книг — часы. Ускорить — `ISR_CONCURRENCY=16` у `pnpm start`, если хватает
  CPU и бэкенд выдерживает.

### 2.3. Проверить локально, перед выгрузкой

```
du -sh build/prerendered/books                         # место (~4–5 ГБ на 315 тыс. книг)
find build/prerendered/books -name '*.html.br' | wc -l # число книг
grep -rl --include='*.html' 'localhost' build/prerendered | head   # пусто = адреса продовые
```

Книги лежат только в `.br`; адреса в них проверить распаковкой:

```
node -e 'const z=require("zlib"),fs=require("fs");const f=process.argv[1];
const h=z.brotliDecompressSync(fs.readFileSync(f)).toString();
console.log(h.includes("localhost")?"ЕСТЬ localhost":"ок", (h.match(/rel="canonical" href="([^"]+)/)||[])[1])' \
  "$(find build/prerendered/books -name '*.html.br' | head -1)"
```

## 3. Выгрузка на прод

Весь `build/` — новым релизом (правило 1):

```
ID=$(date +%Y%m%d-%H%M)
rsync -a --info=progress2 build/ prod:/srv/nexus-web/releases/$ID/build/
rsync -a package.json pnpm-lock.yaml server scripts prod:/srv/nexus-web/releases/$ID/
ssh prod "cd /srv/nexus-web/releases/$ID && pnpm install --prod --frozen-lockfile \
  && ln -sfn \$(readlink /srv/nexus-web/current) /srv/nexus-web/previous \
  && ln -sfn /srv/nexus-web/releases/$ID /srv/nexus-web/current \
  && systemctl restart nexus-web"
```

- rsync передаёт сотни тысяч мелких файлов: первый раз долго, повторно — только изменившиеся,
  если выгружать поверх копии прошлого релиза (`--link-dest=/srv/nexus-web/releases/<прошлый>`
  на стороне прода — неизменённые файлы станут жёсткими ссылками и не займут место).
- Альтернатива — архив: `tar -C build -cf - . | ssh prod "mkdir -p …/build && tar -C …/build -xf -"`
  (один поток, быстрее на множестве мелких файлов).
- После переключения — сброс кэша CDN.

После выкладки прод **не запускает** общую генерацию. Он:

- отдаёт готовые файлы;
- дорисовывает книгу, которой нет на диске (добавлена после дампа), при первом заходе — и дальше
  отдаёт её с диска;
- перерисовывает страницы после правок в админке (бэкенд → `ISR_URL`).

## 4. Как на проде проверить, что страницы — из готовых файлов

### Одна страница

```
curl -sI -H 'Accept-Encoding: br' https://<домен>/books/<slug> \
  | grep -i -E 'content-encoding|content-length|x-static|x-isr|cf-cache-status|x-cache'
```

| Видно | Значит |
|---|---|
| `content-encoding: br` и `x-static: nginx` | готовый `.br` с диска прода, мимо Node — **так и должно быть** |
| `content-encoding: br` и `x-cache: HIT` / `cf-cache-status: HIT` | из кэша CDN (тот же файл) — **так и должно быть** |
| `x-isr: miss` | файла не было, страницу нарисовали сейчас (после — уже с диска) |
| `x-isr: hit` без `content-encoding` | клиент без brotli: Node распаковал файл — нормально только без `Accept-Encoding: br` |
| нет `content-encoding: br` на запрос с br | nginx не нашёл файл или CDN отдал не тот вариант — разбираться |

Клиент без brotli (превью ссылок, старые браузеры):

```
curl -sI https://<домен>/books/<slug> | grep -i -E 'content-encoding|x-isr'
```

→ `x-isr: hit`, без `content-encoding`.

### Много страниц сразу

```
pnpm check-static https://<домен> 200
```

Берёт 200 случайных книг из локального `build/prerendered` (того, что выгружено) и для каждой
делает оба запроса. В конце: сколько отдано из готовых файлов и сколько проблем; код выхода 1,
если хоть одна нарисована заново (`x-isr: miss`) или отдана не в том сжатии.

### В браузере

DevTools → Network → документ книги → Response Headers: `content-encoding: br`, `x-static: nginx`
(или заголовок кэша CDN). В Console — без ошибок гидрации.

### По логам

- nginx прода: запросы `/books/…` с кодом 200 и размером ответа ~8 КБ — с диска.
- Сервер фронтенда (`journalctl -u nexus-web`): обращения к книгам здесь — только клиенты без
  brotli и новые книги. Массовые `ISR` для книг сразу после выкладки — признак, что файлы не
  доехали или nginx их не видит (путь `root`, права на чтение для пользователя nginx).

## 5. Частые проблемы

| Симптом | Причина | Что делать |
|---|---|---|
| Страница открылась, но кнопки не работают, в консоли 404 на `/_app/immutable/…` | HTML от одной сборки, а выложена другая | выкладывать весь `build/` одним релизом; не пересобирать после генерации |
| «Не удалось загрузить. Не найдено» в рецензиях, коллекциях, списках | API бэкенда недоступен по `BACKEND_URL` сервера фронтенда (сайт открыт мимо nginx — `/api` пересылает Node) или nginx не проксирует `/api` | `BACKEND_URL`; в nginx — `location /api/` на бэкенд |
| Обложки не грузятся, canonical на localhost | генерация с `ORIGIN`/`PUBLIC_URL` = localhost | пересобрать с продовыми (п. 2) |
| Клиент видит мусор вместо страницы | CDN отдал `.br` клиенту без brotli | кэш CDN по `Accept-Encoding` (п. 1, CDN) |
| Правка в админке не видна | у бэкенда нет `ISR_URL`/`ISR_SECRET` или фронтенд недоступен из контейнера | проверка связи из п. 1; правка видна не позже чем через 5 минут (кэш браузера и CDN) |
| Все книги идут в Node (`x-isr`), а не с диска | nginx не видит файлы: `root`, права, location книг ниже общего | `nginx -T`, `ls` каталога от пользователя nginx |

## 6. Чек-лист

Один раз:
- [ ] сервер фронтенда как сервис, переменные из п. 1
- [ ] nginx: `map`, location книг, HTTPS, `/_isr/` закрыт
- [ ] бэкенд: `ISR_URL` достижим из контейнера, `ISR_SECRET` совпадает, `PUBLIC_URL` продовый
- [ ] CDN: origin pull, кэш по `Accept-Encoding`, `/api` не кэшируется
- [ ] книги: `BOOKS_ARCHIVES_HOST` (HDD с `.arx`), том `epubcache`, `BOOKS_EPUB_CACHE_MB` под свободное место

Каждый релиз:
- [ ] дамп прода → локальная база, бэкенд с продовым `PUBLIC_URL`
- [ ] `ORIGIN=https://<домен> PRERENDER_ENTITIES=1 pnpm build`
- [ ] `pnpm start` + `pnpm revalidate --all --kind book --wait` — без ошибок
- [ ] проверка на localhost-адреса в страницах
- [ ] выгрузка всего `build/` новым релизом, переключение симлинков, рестарт, сброс CDN
- [ ] `pnpm check-static https://<домен> 200` — проблем 0
