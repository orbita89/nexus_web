# Вопросы и предложения к бэкенду

Код бэкенда из фронтенда не меняем — собираем сюда, решаем в `nexus_project`.

## Ошибки в контрактах (мешают генерации типов)

1. **`social.json` ссылается на схемы, которых нет:** `ReviewSort` (`GET /entities/{slug}/reviews`,
   параметр `sort`) и `ThreadSort` (`GET /threads`, `GET /entities/{slug}/threads`). openapi-typescript
   падает. Сейчас `scripts/api-types.mjs` подставляет `string` — фронтенд теряет список значений.
   Нужно добавить схемы в components (вероятно, не зарегистрированы в `#[openapi(components(...))]`).
2. **`operationId` не уникальны** во всех трёх контрактах (OpenAPI требует уникальности):
   `openapi.json` — `login`, `list`, `start`; `catalog.json` — `create`, `delete`, `update`, `list`,
   `get`; `social.json` — `create`, `get`, `delete`, `update`, `list_for_entity`, `get_own`,
   `list_for_user`. utoipa берёт имя функции. Сейчас скрипт переименовывает повторы
   (`get_collections_id`). Лучше задать `operation_id` в `#[utoipa::path]` или префикс модуля.

## Dev-окружение

3. **Ссылки из писем и OAuth в dev ведут на бэкенд.** `APP_BASE_URL=http://localhost`, а nginx
   отдаёт `/` приложению. Сейчас обход — `APP_BASE_URL=http://localhost:5173` в `infra/.env`
   (описано в README фронтенда). Когда фронтенд поедет в docker: nginx `/` → фронтенд,
   `/api`, `/ws`, `/docs` → приложение.

## Чего не хватает в API

4. **Задан ли пароль.** В `UserView` нет признака вроде `has_password`. Без него фронтенд не знает,
   спрашивать ли пароль при смене email (`POST /me/email`) и показывать ли «Сменить пароль» или
   «Задать пароль» (через сброс). Сейчас поле пароля необязательное, с подсказкой.
5. **Машинные коды ошибок.** `{"error": "..."}` — английский текст; фронтенд сопоставляет строки
   (`email not verified`, `conflict: username already taken`, ...). Любая правка формулировки
   ломает перевод. Предложение: `{"error": "...", "code": "email_not_verified"}` — поле добавочное,
   старые клиенты не заметят.
6. **429 без срока.** Есть ли `Retry-After`? Если добавить, фронтенд покажет «попробуйте через 80 с»
   вместо общего «подождите».

## Надёжность сессий

7. **Окно повтора для refresh.** Если вкладку закрыли, пока `POST /refresh` в пути, сервер токен
   заменил, а клиент новый не сохранил. Следующий refresh старым токеном выглядит как кража и
   отзывает все сессии пользователя. Частая практика — короткое окно (10–30 с), в которое повтор
   заменённого токена возвращает ту же новую пару, а не считается кражей. Очередь на фронтенде
   (Web Locks) закрывает гонки вкладок, но не этот случай.
