# Вопросы и предложения к бэкенду

Код бэкенда из фронтенда не меняем — собираем сюда, решаем в `nexus_project`.

## Dev-окружение

1. **Ссылки из писем и OAuth в dev ведут на бэкенд.** `APP_BASE_URL=http://localhost`, а nginx
   отдаёт `/` приложению. Сейчас обход — `APP_BASE_URL=http://localhost:5173` в `infra/.env`
   (описано в README фронтенда). Когда фронтенд поедет в docker: nginx `/` → фронтенд,
   `/api`, `/ws`, `/docs` → приложение.

## Чего не хватает в API

2. **Машинные коды ошибок.** `{"error": "..."}` — английский текст; фронтенд сопоставляет строки
   (`email not verified`, `conflict: username already taken`, ...). Любая правка формулировки
   ломает перевод. Предложение: `{"error": "...", "code": "email_not_verified"}` — поле добавочное,
   старые клиенты не заметят.

3. **Сортировка `GET /entities`.** Сейчас только «новинки сверху». Для каталога нужны «популярное»
   и «по оценке» (`sort=popular|rating|new|title`), иначе главная и разделы не могут показать
   лучшее. В `catalog.md` это уже в планах (🕓).
4. **Оценка в списках.** В `EntitySummary` нет средней оценки, а сводка — отдельный запрос
   `GET /social/entities/{slug}/rating` на каждую сущность (24 на страницу, и на SSR тоже).
   Поэтому в сетках оценок нет, только на карточке. Варианты: `rating_average`/`rating_count` в
   `EntitySummary` (денормализация в catalog) или пакетный
   `GET /social/ratings?slugs=a,b,c` → `{slug: {average, count}}`.
5. **Год в `EntityRef`.** В темах форума, рецензиях профиля и коллекциях сущность приходит как
   `EntityRef` без даты: у темы про «Дюну» плашки «Дюна · Дюна · Дюна» (книга и фильмы 1984 и 2021) не различить. Просьба добавить `release_date` (как в `EntitySummary`).
6. **`GET /tags/{slug}`.** Страница тега берёт название из `GET /tags` целиком — пока тегов
   немного, это нормально; при росте нужен эндпоинт одного тега.

## Надёжность сессий

7. **Окно повтора для refresh.** Если вкладку закрыли, пока `POST /refresh` в пути, сервер токен
   заменил, а клиент новый не сохранил. Следующий refresh старым токеном выглядит как кража и
   отзывает все сессии пользователя. Частая практика — короткое окно (10–30 с), в которое повтор
   заменённого токена возвращает ту же новую пару, а не считается кражей. Очередь на фронтенде
   (Web Locks) закрывает гонки вкладок, но не этот случай. **Ловится на практике:** две полные
   загрузки страниц подряд (быстрое «обновить» или переход до окончания refresh) обрывают refresh
   в пути, и пользователя выбрасывает из всех сессий. В e2e приходится ждать восстановления сессии
   после каждой полной загрузки.

## Решено

- Схемы `ReviewSort`, `ThreadSort` и уникальные `operationId` в контрактах. `pnpm api:types` теперь
  падает с понятным сообщением, если контракт снова сломается, а не обходит ошибку.
- `has_password` в `UserView`: пароль при смене email и «Задать пароль» вместо смены — по нему.
- `Retry-After` и `retry_after` у 429: фронтенд пишет «Попробуйте через 80 с».
- Трейлеры: вместо предложенного `trailer_url` (видеофайл) — `metadata.trailers`, источники по
  приоритету (YouTube, Rutube), плеер в модалке по кнопке. Сейчас в ветке
  `feature/catalog-trailers` (поверх `fix/contract-and-auth-fields`), в `main` бэкенда ещё нет.
